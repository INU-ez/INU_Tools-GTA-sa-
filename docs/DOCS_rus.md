## Установка

1. Скачайте папку `INU_tools/` (или zip-архив)
2. Поместите `INU_tools/` в папку аддонов Blender:
   - **Windows:** `%APPDATA%/Blender Foundation/Blender/<версия>/scripts/addons/`
   - **Linux:** `~/.config/blender/<версия>/scripts/addons/`
   - **macOS:** `/Users/<имя>/Library/Application Support/Blender/<версия>/scripts/addons/`
3. Blender → Edit → Preferences → Add-ons → включите **"INU_tools(gta_sa)"**

**Требования:**
- Blender 2.83+ (4.2+ для установки через extensions.blender.org)
- Itera Tools 3 — опционально, для vertex lighting

**Сохранение настроек:** все пути (Game Root, IDE, IPL, IMG, текстуры) сохраняются в `INU_Preset/paths.json` рядом с папкой аддонов. Настройки переживают обновления аддона и восстанавливаются автоматически при запуске Blender.

## Быстрый старт

### Экспорт модели в GTA SA

1. Назовите объекты с суффиксами: `mybuilding_DFF`, `mybuilding_COL`, `mybuilding_LOD`
2. Задайте **Model ID**, **TXD Name**, **Draw Distance** в свойствах объекта (`obj.inu`)
3. Выделите все, нажмите **Export All** → выберите папку
4. Результат: `mybuilding.dff`, `mybuilding.col`, `LODmybuilding.dff`, `mybuilding.txd`

### Импорт карты GTA SA

1. Укажите **Game Root** — папку GTA SA (например `D:\GTA San Andreas\`)
2. Нажмите **Извлечь ресурсы** — извлечёт DFF/COL/текстуры из IMG в `.inu_cache/` (один раз, ~8 с на район)
3. Нажмите **Импорт карты** — импорт только из кеша, ~30 с на район размера LA

### Горячие клавиши

| Клавиша | Действие |
|---------|----------|
| `Shift+T` | Открыть/закрыть UV Editor |
| `Shift+A` | Добавить модель GTA SA (Army.dff / Admiral.dff) |

Пять свободно-плавающих GPU-окон дают одним кликом доступ к самым частым операциям без скролла N-sidebar:

| Окно | Что внутри | Открыть |

| **Import / Export** | Selection-диагностика, меню Import/Export, Auto TXD + DXT backend, Pipeline picker (Vehicle/D-N/Building/Ped), DFF Flags (collapsible) | 🪟 в шапке панели **Export** |
| **Validation** | Результаты pre-export проверки (кватернионы, paintjob, modulate color, парность _ok/_dam) с one-click фиксами | 🪟 в шапке панели **Проверка** |
| **Освещение** | Селектор пресета прелайта, 8-lamps toggle, Day/Night vcol контролы, bake, copy, LightMap row | 🪟 в шапке панели **Prelight** |

Каждый floater можно **таскать** (за любую не-кнопку), **сворачивать** в title bar, **пинить к workspace** (Lock icon — отображается только в пинённом workspace'е), использует палитру текущей темы Blender. Позиция сохраняется в `.blend`.

## Поддержка нескольких игр (III / VC / SA)

Активная игра выбирается вверху панели **GTA Tools** в N-sidebar — три кнопки **San Andreas / Vice City / GTA III**. Все экспортёры, валидация и lint используют этот выбор. По умолчанию — San Andreas (основная цель аддона). Импорт авто-детектит игру по файлу и либо переключает сцену (если она пустая), либо предупреждает.

### Матрица форматов

| Формат | III (RW 3.3) | VC (RW 3.5) | SA (RW 3.6) |
|---|:-:|:-:|:-:|
| **DFF** чтение | ✅ авто-детект по RW версии | ✅ | ✅ |
| **DFF** запись | ✅ (без SA-only Night vcols, Pipeline, UV anim) | ✅ (без Night, Pipeline) | ✅ |
| **COL** | ✅ `COLL` v1 | ✅ `COL2` v2 | ✅ `COL3` v3 |
| **TXD** | ✅ (RW lib_id под игру) | ✅ | ✅ |
| **IDE** | ✅ (5-полевой OBJS, без `txdp`/`2dfx`) | ✅ (5-полевой, без `2dfx`) | ✅ (multi-mesh, `txdp`, `2dfx`) |
| **IDE cars** | 12 колонок | 13 (+ `anims`) | 15 (+ flags, wheel split) |
| **IDE peds** | 7 колонок | 10 (+ anim_file, radio×2) | 14 (+ flags, voice×3) |
| **IPL inst** | 12 колонок (scale, без interior) | 13 (interior + scale) | 11 (lod_index, без scale) |
| **IPL binary** | — | — | ✅ `bnry` |
| **IMG** | ✅ VER1 (раздельные `.dir` + `.img`) | ✅ VER1 | ✅ VER2 |
| **IFP** | ✅ ANPK chunked | ✅ ANPK | ✅ ANPK + ANP3 сжатый |
| **2DFX хранится** | в IDE `2dfx` секции | в IDE `2dfx` | в DFF chunk 0x253F2F8 |
| **2DFX типы** | Light, Particle, Strobe | + PedAttractor, SunGlare | + Type 5 (IDE-only) |
| **Surface IDs** | 0–84 (clamp на запись) | 0–85 | 0–178 |
| **model_id потолок** | 6500 | 8500 | 19999 |

### Переключение игр

**Вручную:** кликни III / VC / SA в шапке GTA Tools.

**Автоматически при импорте:** в file-browser dialog'ах импорта (DFF/COL/IPL/TXD/IMG) есть дропдаун «Игра» с дефолтом **Авто**. Авто читает заголовки/колонки файла и проставляет правильную игру на импортируемые объекты. Если найденная игра отличается от активной в сцене:

- **Свежая сцена (game=SA + 0 INU-объектов):** scene авто-флипается на найденную.
- **Заполненная сцена:** WARNING — `Импортированный файл = VC, но активная игра сцены = SA. Переключи вкладку GTA Tools на «VC»`. Переключение остаётся ручным чтобы избежать сюрпризов в mixed-game проектах.

### Cross-game перевод данных (lossy)

Когда импортируешь III файл и экспортишь в SA (или наоборот), writer прогоняет данные через канонические категории, чтобы байты соответствовали ожиданиям целевого engine.

- **COL surface IDs** — 12 канонических категорий (TARMAC, GRASS, WOOD, METAL, GLASS, …) через `core/surface_translate.py`. 178 SA-поверхностей схлопываются в ~12 категорий при cross-game; SA → VC → SA теряет под-типы вроде `GRASS_SHORT` vs `GRASS_LONG`. Каждый материал несёт `inu.col_source_game` так что перевод срабатывает только при реальной смене игры.
- **IDE objs.flags** — биты значат разное в разных играх. Пример: бит `0x20` в III/VC = `IGNORE_LIGHTING`, в SA — только для анимированных. `core/ide_flag_translate.py` переводит через 19 канонических категорий. UI показывает только чекбоксы валидные для активной игры (III=6, VC=10, SA=15).
- **PEDS cars_can_drive** — VC вставил `normal` в bit 0, сдвинув позиции III на +1. `core/ped_mask_translate.py` re-mapит через канонические class-имена. `IdePed.source_game` тагает импортированных peds.

### Validate Scene — cross-game предупреждения

Когда сцена нацелена на III/VC, но объекты несут SA-only фичи, **Проверка перед экспортом** их флагает:

- `model_id > vanilla_max` (потребует FLA)
- `has_night_vcols` (SA-only RW extension)
- `has_multi_mesh_lod` (downgradeится в single-mesh)
- `has_uv_anim_material` (III-only; UV anim требует RW 3.5+)
- `fx_2dfx_ids` вне per-game allowlist

### Известные ограничения

- **Full map round-trip — только для SA.** III/VC модеры могут импортить vanilla DFF/COL/TXD/IDE/IPL/IMG по отдельности, но Map Import pipeline (district auto-split, bulk IMG rebuild) изначально написан под SA data layout.
- **Asset Library Builder — SA-only.** Future work — нужны III/VC source parser'ы.
- **IFP** — ANP3 (сжатый int16) родной для SA; III/VC авто-downgradeятся в ANPK с warning'ом если забудешь переключить формат экспорта.
- **2DFX импорт для III/VC IDE** создаёт placeholder Empty'и (позиция + тип + цвет), с raw type_params stashed на Empty для byte-identical re-export. Per-type Blender-prop mapping (corona texture, particle name, attractor behaviour) частичный — Light и Particle wired; PedAttractor / SunGlare / Strobe re-emit'ятся через stashed params.

## Готовые рецепты (workflows)

Каждый рецепт — это конкретная задача от и до: от «что лежит в Blender» до «что появляется в игре».

### Рецепт: Кастомное здание (DFF+COL+LOD+TXD)

**Цель:** добавить статичный объект (дом, прop, забор) в карту GTA SA.

1. **Подготовь меши** в Blender:
   - HD-меш с уникальными UV → переименуй в `myhouse_DFF`
   - LOD (упрощённый, ~30% полигонов) → `myhouse_LOD`
   - Collision (грубый, всё в треугольниках) → `myhouse_COL`
2. **На HD-меше** Properties → Object → INU Tools:
   - Model ID: 18000 (свободный из 18000-19999)
   - TXD Name: `myhouse`
   - Draw Distance: 299
3. **На COL-меше** Properties → Material → COL Surface Type: выбери тип (Asphalt / Concrete / Glass / ...)
4. **Текстуры** на материалах HD — назначь PNG/JPG/TGA как Image Texture (можно перетащить из проводника).
5. **Выдели все три меша** → N → **Экспорт / Импорт** → **Импорт** → **Экспорт** не нажимай (для batch — отдельная кнопка):
   - В секции **«Массовый экспорт»** включи галки `DFF`, `COL`, `LOD`, `TXD`
   - **«В папку»** → выбери папку
6. **Получишь:** `myhouse.dff`, `myhouse.col`, `myhouse_LOD.dff`, `myhouse.txd`
7. **В игру:** скопируй `.dff` и `.col` в `gta3.img` (через IMG Tool / IMG Manager), `.txd` тоже туда.
8. **IDE entry:** добавь в `gta.dat` через панель **IDE / IPL / IMG** → IDE → **Добавить**.
9. **IPL placement:** положи объект в сцене где надо → **IPL** → **Экспорт** в нужный `.ipl` или **Карта** → **Экспорт карты**.

**Подводные камни:**
- LOD ID = HD ID + 1 (auto), либо вручную с суффиксом `LODmyhouse` — IDE flags = 4
- Если `myhouse.txd` не появляется в игре — нажми **IMG Rebuild** (см. memory `IMG Rebuild stale`)

### Рецепт: Кастомная машина с damage variants

**Цель:** машина, у которой при крушении меняются части (`_dam` варианты).

1. **Базовая модель:** `bonnet`, `bumper_lf`, `bumper_rf`, `chassis`, `door_lf`, ...
2. **Создать damage-варианты:** N → **Машины** → **Создать _dam** на выделенной части (например `bonnet`). Получишь `bonnet_dam` — это будет деформированная версия.
3. **Деформируй `_dam`** в Edit Mode (вмятины, гнутый металл).
4. **Проверка пар:** **Машины** → **Проверить пары** — операция выводит отчёт о всех парах `_ok/_dam` в сцене.
5. **Hierarchy:** все части привязаны к `chassis_dummy`. Колёса — к `wheel_*_dummy`. Это критично для физики игры.
6. **Damage states preview:** **Показать: OK / Dam / Оба** — переключает видимость пар в Blender для визуальной проверки.
7. **Экспорт:** выдели всю иерархию (alt+click на корне → выделение детей) → **Экспорт DFF** через menu.
8. **vehicle.txd / vehicle.col:** обычно общие для всех машин. Используй **Общий TXD** toggle в правой панели **Экспорт TXD** диалога.
9. **IDE entry в `vehicles.ide`:** секция `cars` — handling_id, wheel_id и т.д. (см. таблицу в **IDE**).

**Подводные камни:**
- Нужны строго имена `xxx_ok` / `xxx_dam` (разделитель `_dam`, не `_damage`)
- Wheel scale в IDE влияет на физику, не на визуал

#### Paintjob (Pay'n'Spray альтернативные раскраски)

GTA SA умеет менять текстуру кузова машины при покупке paintjob'а в Pay'n'Spray. Технически это **подмена текстуры** на лету: игра берёт текстуру `<vehname>_paintjob1` или `<vehname>_paintjob2` из vehicle.txd и подставляет вместо основной.

**Workflow в INU:**
1. На материале кузова в **Properties → Material → INU Effects → Paintjob (Pay'n'Spray)** заполни оба слота:
   - **Раскраска 1** — изображение для `<base>_paintjob1`
   - **Раскраска 2** — изображение для `<base>_paintjob2`
   где `<base>` — имя основной текстуры (того что назначено как Image на материале).
2. Кнопка **✓** (рядом с заголовком) запускает **Validate Paintjobs**: проверяет что у всех материалов с paintjob'ами заполнены оба слота и есть основная текстура.
3. При экспорте TXD оба альтернативных файла автоматически добавляются в архив с правильными именами.
4. В игре paintjob применяется через скрипт (Pay'n'Spray) — никакого ручного указания имён.

**Подводные камни:**
- Нужны **оба** слота — игра молча игнорирует paintjob если не хватает одного из двух
- Имена альтернатив рассчитываются от **подключённой** Image-ноды материала. Если у материала нет видимой Image — INU пропустит paintjob (валидатор это покажет)
- Размеры альтернативных текстур должны совпадать с основной (иначе игра растянет / обрежет)

### Frame Hierarchy Editor

**Где:** N → GTA Tools → **Иерархия фреймов** (видна когда выделен любой объект)

**Что делает:** показывает дерево детей активного объекта + 6 операторов для безопасного редактирования DFF Frame List:

| Кнопка | Что делает |
|---|---|
| **Rename** | Переименовать активный фрейм (popup). Ставит `dff_frame_write_name=True` чтобы новое имя попало в DFF при экспорте |
| **Set Parent** | Активный объект становится родителем для остальных выделенных. Сохраняет world-transform, сбрасывает `matrix_parent_inverse` в identity (DFF requirement) |
| **Unparent** | Снять parent с выделенных, мировая позиция сохраняется |
| **Validate Vehicle** | Проверка против vanilla SA шаблона машины (`chassis_dummy`, `wheel_lf_dummy` и т.д.). Сообщает о пропущенных и подозрительных именах в System Console |
| **Validate Ped** | Проверка против 31-кости шаблона педа (case-sensitive: `Pelvis`, `R UpperArm`...) |
| **Зеркало L↔R** | Для выделенных с `_lf`/`_lb` в имени создаёт зеркальные `_rf`/`_rb` копии (X отражён). Если зеркало уже существует — пропускает |

**Когда использовать:**
- Делаешь машину с нуля → собрал основу с `_lf` → клик «Зеркало L↔R» → пол-машины готово
- Импортировал DFF из GTA3/VC и переименовываешь под SA-стандарт
- Перед экспортом машины/педа → клик Validate, читаешь System Console чтобы поймать опечатки до игры

**Подводные камни:**
- Validate Vehicle игнорирует регистр (`Wheel_LF`, `wheel_LF` = одно), но игра требует строго `wheel_lf_dummy`. Validate Ped — case-sensitive (там exact match)
- Set Parent работает на любых типах (MESH/EMPTY/ARMATURE) — для DFF-фреймов важно чтобы parent был тоже DFF-фрейм, а не случайный объект сцены

### Рецепт: Скиннутый персонаж (Skinned Ped)

**Цель:** заменить ped на свою модель.

1. **Импорт vanilla `cs_player.dff`** как референс — увидишь иерархию из 31 кости.
2. **Меш одет в Armature** через Object → Parent → With Automatic Weights, либо вручную через Vertex Groups.
3. **Совпадение имён костей** с vanilla скелетом критично — `Pelvis`, `Spine`, `Spine1`, `Neck`, `Head`, `R UpperArm`, ... Проверка: **Проверка** → **Validate Action Bones**.
4. **Vertex weights:** макс 4 кости на вершину (GTA SA limit). Лишние снимаются автоматически при экспорте.
5. **Экспорт:** **Экспорт DFF** → имя `cs_myped.dff`.
6. **IDE peds entry:** `peds.ide` → секция `peds`.
7. **Animations:** все стандартные анимации (`ped.ifp`) применяются автоматически — главное чтобы имена костей совпадали.

**Подводные камни:**
- Если меш «лежит плашмя в игре» — проверь rest_quat (см. memory `IFP export round-trip fix`)
- Если кости не двигаются — это `bl_quat` rotation order, проверь **Validate Action Bones**

### Рецепт: Animated Map Object (мельница, кран, пропеллер)

**Цель:** статичный объект на карте у которого крутится одна или несколько частей (лопасти мельницы, стрела крана, флюгер, дверь ворот, лопасти вентилятора).

INU автоматизирует **три артефакта** которые игре нужны:

| Файл | Что внутри |
|------|------------|
| `<base>.dff` | Frame-иерархия + HAnim PLG + меши |
| `<base>.ifp` | Анимация с tracks-ами на имена кости |
| IDE `anim` запись | `model_id, model_name, txd_name, anim_file, drawdist, flags` |

---

#### Полный пайплайн

**1. Подготовка мешей**

Раздели объект на **статичную часть** (`mill_base`) и **анимированную** (`mill_blades`). Назови коротко (см. правила ниже). На анимированной меше выстави **Model ID** в Object → INU Tools → Model ID.

**2. Создание rig'а через пипетку**

Открой `N → GTA Tools → Анимации → таб «Объекты»`. В боксе **Animated Map Object** работает пипетка.

| Состояние | Действие |
|-----------|----------|
| Rig нет, выделен меш | Подсказка «Статика: `<имя>`». Жми пипетку → клик по **анимированному мешу** в viewport. Rig создаётся: активный меш → root (статика), picked → pivot1 (анимированный). |
| Rig уже есть | Подсказка «Target rig: `<root_name>`» + radio «Куда» (К pivot / К root). Пипетка → клик по следующему мешу → парентится в выбранную ветку. |

Результирующая иерархия:
```
mill_root           Empty (ARROWS)    bone_id=0   ← корень
├── mill_base                                      ← статичный меш
└── mill_pivot1     Empty (SPHERE)    bone_id=1   ← вращается
    └── mill_blades                                ← анимированный меш
```

**3. Настройка pivot'а**

Выдели pivot (`mill_pivot1`) → появится бокс **«Настройки: mill_pivot1»** с live-edit слайдерами:

- **Ось вращения:** Z (лопасти) / Y (пропеллер) / X (шлагбаум)
- **Оборотов за цикл:** 1
- **Длительность:** 60 кадров
- **Цикличность:** ✓

**4. Multi-part rig (опционально)**

Кнопка **«+Pivot»** в том же боксе → создаёт `mill_pivot2`. Пипеткой парентишь к нему второй анимированный меш. В IFP попадут **оба** track'а в одной анимации.

**5. Validate**

Кнопка **«Validate»** в том же боксе — проверяет иерархию, bone_ids, Action'ы, парентинг. Проблемы выводятся в Info area.

**6. Export**

Сверху в табе «Объекты» — кнопка **`DFF+IFP+IDE`**. Откроется диалог:

- **Папка / Базовое имя / TXD / Model ID / Draw distance** — настройки выхода
- **Дописать IDE запись:** ✓ — добавит в `anim`-секцию файла из `Scene → INU Tools → IDE Path`
- **Имя IFP** + **Режим IFP** (Дополнить / Перезаписать) — для бандлинга нескольких rig'ов в один файл

Перед экспортом можно выделить **любой объект rig'а** (Empty / pivot / меш) — экспортёр найдёт rig автоматически.

**7. Размещение в игре**

1. **DFF + TXD + IFP** → все три файла **в `gta3.img`** (НЕ в loose-папку `anim/`!)
2. **Rebuild Archive** в IMG-туле
3. **IPL** — размести через `Object IDE/IPL` → IPL Export. Игра анимирует везде где есть `inst <model_id>` запись.

#### 🚨 Правила и ограничения

**Эти 4 пункта обязательны — нарушение крашит игру или ломает анимацию:**

| Правило | Что будет если нарушить |
|---------|------------------------|
| **Длина имени модели ≤ 12 символов** | Крэш `0x534134` (access violation в HAnim parser) при появлении модели в радиусе draw distance |
| **Имя анимации в IFP = `model_name` в IDE** | Игра не найдёт анимацию → молча не применит (без крэша). INU делает автоматом, но если правишь IDE руками — следи. |
| **IFP должен лежать в `gta3.img`** | Streaming не сканирует loose-файлы в `anim/` для map objects. IFP должен быть **внутри** IMG-архива. |
| **IDE-запись в секции `anim`** (не `objs`) | Игра загрузит как статичный объект, IFP не применит. INU автоматом ставит в `anim`. |

**Прочие важные моменты:**

- **Model ID на статичном меше = `0`** — только анимированный меш получает реальный ID
- **Имя rig'а наследуется от первого меша** при пипетке. Хочешь префикс `mill` — переименуй первый меш в `mill_base` ДО пипетки.
- **Кнопка «Экспорт»** в том же табе — это standalone IFP операция для armature. Для Empty-rig используй **`DFF+IFP+IDE`**.

#### 🛑 Подводные камни (диагностика)

**Crash при появлении модели:**

| Симптом | Что проверить |
|---------|---------------|
| Игра закрывается без сообщения | 1) Длина имени ≤ 12? 2) IDE-запись в `anim`? 3) IFP в `gta3.img` (не в `anim/`)? 4) Rebuild IMG после замены? |
| Crash log говорит `0x534134` | Имя модели/кости слишком длинное — переименуй короче |
| Crash log говорит другой адрес | Проблема не в анимации — изолируй: временно перенеси запись в `objs` (флаг=0). Если стартует → копай в анимации. Если падает → проблема в другом моде. |

**Модель грузится, но анимации нет:**

| Симптом | Что проверить |
|---------|---------------|
| Имя анимации в IFP = `'????????'` (вопросы) | Был Action с кириллицей. INU теперь форсит ASCII имя, переэкспортируй. |
| Animation name ≠ model name | Проверь что 2-е поле IDE (`model_name`) совпадает с именем анимации внутри IFP |
| Дубликат имени в нескольких IDE | Удали одну из записей — один model_name на весь проект |
| Забыл Rebuild Archive | После замены файла в IMG **обязательно** Rebuild |

**DFF stepping (анимация рывками):**
- Кватернионы не нормализованы. В v2.0.0 пофиксено через `bl_quat.normalize()`. Если на старой версии — обнови или переэкспортируй после обновления.

#### 🔬 Технические детали (для разработчиков)

INU автоматически выставляет всё что нужно — обычному пользователю эту секцию читать не обязательно. Но если что-то пошло не так и хочется понять как именно — вот что делается под капотом:

**DFF:**
- HAnim PLG на root с полным bone tree + минимальный HAnim на каждом pivot
- `bone_type` в bone list: `[0, 1]` для 2-х костей, `[0, 3, 0, ..., 1]` для большего числа (точное совпадение с ванильным RW)
- `frame.flags = 0x20003` на root (без этого HAnim hierarchy walker валит игру)
- ATOMIC `flags = 5` (render + collision)
- DFS-сортировка: Empty с `inu_bone_id` идут первыми → pivot становится `idx=1` (как в ванилке)

**IFP:**
- Формат **ANP3** (SA compressed, совпадает с counxref.ifp / airport.ifp)
- `bone_id = -1` для всех костей (игра матчит по имени фрейма, не по ID)
- Первый keyframe нормализуется в `t=0.0` через `(frame - frame_start) / fps`
- Root исключён из IFP — `inu_animobj_empty_root` skip-ится

**Skinned ped'ы:** Empty-rig только для **map-объектов**. Скиннутые персонажи используют armature + IK-rig флоу (`ik_rig.py`).

### Рецепт: Анимация IFP с round-trip проверкой

**Цель:** создать кастомную анимацию для ped и записать в IFP.

1. **Импорт скелета:** `cs_player.dff` или твой кастомный с armature.
2. **Импорт референс-IFP:** **Анимации** → **Импорт IFP** → `ped.ifp`. Получишь все standard действия как Blender Actions.
3. **Создай новое действие:** в Action Editor (Dope Sheet) → New → анимируй keyframes.
4. **Назови действие** так как игра будет вызывать (например `ANIM_DANCE_LOOP`).
5. **Round-trip проверка перед экспортом:** **Проверить round-trip** — экспортирует и читает обратно, сравнивает. Защищает от регрессий типа «лежит плашмя».
6. **Экспорт:** **Экспорт IFP** → отдельный файл, либо **Добавить в IFP** → доклеить в существующий.
7. **Live preview:** включи **Preview ●** — анимация играет в viewport без перехода в режим animation.

**Поддерживаемые форматы:** ANP3 (default GTA SA), ANPK (GTA3/VC), ANP2.

**Подводные камни:**
- Если в игре анимация рывками — проверь `kf.time` единицы (canonical = seconds)
- Source format сохраняется при импорте — экспорт по умолчанию пишет в исходном формате

### Рецепт: IK Rig для SA peds

**Цель:** анимировать персонажа GTA SA в режиме IK (тяни ступни / кисти, всё остальное доводит обратная кинематика) вместо ручной FK-крутки каждой кости.

**Где:** N → GTA Tools → **Анимации** → таб **CHAR** → **Add IK Rig** (на выделенный Armature).

**Что делает Add IK Rig:**
- Создаёт control-кости **внутри той же Armature** (никаких внешних Empty или вспомогательных rig'ов): на запястьях/ступнях — IK target кубики, на локтях/коленях — pole-маркеры, на голове/торсе — control-кости, плюс `Root` master-control в основании.
- Накидывает `IK` constraint на руки/ноги (chain length=2, target — control-куб), `Copy Rotation` на голову/торс/кисть/ступню (нужно для сохранения rest pose).
- **Brute-force pole_angle калибровка**: проходит несколько углов и выбирает тот при котором локоть/колено остаётся в исходном положении — работает с любым `bone roll` (vanilla SA или custom скин).
- **FK → IK bake**: если на armature уже есть Action — все его keyframe'ы конвертируются в ключи на новых control-bones (visual_key bake). Старая анимация играет идентично, но теперь редактируется через IK.
- Custom-shape всех control-bones — wireframe кубики, цветом по теме (по умолчанию зелёный THEME09).

**Размер и видимость кубов:**
- В Анимации → **Дополнительно** есть слайдер **Множитель размера** (общий) и **Смещение куба руки/ноги** (отдельно для конечностей).
- 4 toggle'а: `Руки/ноги`, `Локти/колени`, `Голова/торс`, `Корень` — скрывают/показывают разные группы control-bones (видимость через `bone.hide`, не удаление).

**Floor limiter (`INU_Ground` plane):**
- В **Дополнительно** → **Пол** → `Создать INU_Ground` → появляется dev-текстурированная плоскость 10×10 м с `dev_anim.png`.
- Все foot IK targets автоматически получают `Floor` constraint с offset = `gtatools_floor_offset` (по умолчанию 0.05 м). Ступни не проваливаются под пол.

**Bake & Clear IK** — перед экспортом IFP:
1. Запекает текущий IK-результат обратно в FK keyframes на deform-bones (visual_key).
2. Удаляет все control-bones, IK constraints, Copy Rotation.
3. Action остаётся идентичным визуально, но работает на чистом FK — IFP-экспорт не должен видеть control-bones (иначе игра падает с лишними костями).

**Workflow:**
1. Импорт ped DFF (`cs_player.dff` или свой) → Armature + меш.
2. **Add IK Rig** на Armature → готов к работе.
3. В Pose Mode — двигай только зелёные кубики, не deform-bones.
4. Когда анимация готова → **Bake & Clear IK** → **Экспорт IFP**.

**Подводные камни:**
- POSE vs REST: если делаешь `Add IK Rig` пока armature в pose-position-not-rest — control-кости создадутся не в том месте. Перед Add: Pose → Clear All Transforms.
- Вручную не двигай deform-bones кисти/ступни после Add — это перетрёт IK target положение.
- На скинах с custom bone roll FK→IK bake может «извести» старые ключи — поэтому brute-force pole_angle помогает, но иногда нужна ручная подгонка `pole_angle` после.
- `Bake & Clear IK` визуально не отличается от исходного FK — проверяй scrub'ом таймлайна перед экспортом.

### Рецепт: Профили N-sidebar (наборы видимых панелей)

**Цель:** скрыть лишние панели в зависимости от того что делаешь — **«сейчас работаю над машиной»** не нужны Map Workflow и Water Geometry, а **«делаю карту»** наоборот не нужна Vehicles панель.

**Где:** N → GTA Tools → шапка панели «GTA Tools» — dropdown **Профиль** (по умолчанию `ALL` = все панели видимы).

**Что делает:**
- Профиль = **JSON-файл** в `<addons>/INU_Preset/profiles/<name>.json` со списком `order` (порядок панелей) и `hidden` (что спрятать).
- При выборе профиля → `is_panel_visible(idname, profile)` фильтрует `poll()` каждой панели + `bl_order` устанавливает порядок.
- Состояние профиля живёт на Scene-проперти `gtatools_profile`, сохраняется с .blend.

**Создание своего профиля:**
1. Dropdown **Профиль** → `+` → popup с двумя списками:
   - Слева — все панели аддона
   - Справа — порядок (drag-pick: клик в списке → пункт уехал в порядок)
2. **👁** напротив панели — скрыть/показать.
3. **Имя профиля** + **Описание** → **Создать**.
4. JSON автоматически сохранён → доступен в dropdown.

**Редактирование/удаление:** dropdown → `▾` (edit) или `−` (delete).

**Шаринг между членами команды:** скопируйте JSON из `INU_Preset/profiles/` → друг кладёт к себе → видит профиль в dropdown.

**Built-in профиль `ALL`:** показывает всё, не редактируется/не удаляется. На него происходит fallback если JSON битый или профиль не найден.

**Подводные камни:**
- Профили — **визуальные**, не запрещают использовать панели. Если нужно «скрыть от других» опции — это не инструмент для прав доступа.
- Reorder применяется при следующем рисовании панели — иногда видно «прыжок» при первом клике.
- Имя профиля валидируется: запрещены `/`, `\`, `..`, длина <100 символов (защита от path traversal).

### Рецепт: Vertex Colors / Prelight для здания

**Цель:** статичное освещение «запечь» в vertex colors здания, чтобы интерьеры выглядели атмосферно без real-time света.

1. **Lighting** (N → GTA Tools → **Lighting**) → **Prelight** подпанель.
2. **Создать Day/Night атрибуты:** в секции **Цветовые атрибуты** клик `Day/Night`. Получишь два color attribute layer — для дневного и ночного освещения.
3. **Поставь источники света** в Blender (Sun + Spot для окон).
4. **Запечь:** **Запечение** → **С тенями** (raycast). Запечётся в активный атрибут (Day или Night).
5. **Переключение Day↔Night** — выбираешь активный, пере-запекаешь с другим освещением.
6. **Контроль яркости:** **V offset** — глобальное смещение брайтнес.
7. **Per-layer контроль:** **Слои Vertex Color** — composite из нескольких layers с opacity/contrast/brightness.
8. **Превью в Blender:** **Show preview** (HIDE_OFF icon) — переключает между renderable и flat-show.
9. **Экспорт DFF** автоматически включит Day и Night колора в чанки `prelit` + `extra_vert_colors`.

**Подводные камни:**
- Если в игре вертекс-цвета мерцают «как прилайт» — снять `Modulate Color` в DFF Flags (см. memory `Modulate Color flicker`)
- LightMap через UV2 — отдельная фича, не путать с vertex colors

### Рецепт: Размещение объекта на карте через IPL

**Цель:** разместить кастомный объект в конкретной точке карты GTA SA.

1. **Объект уже в IDE** (см. рецепт «Кастомное здание»).
2. **В Blender** перенеси объект в нужную позицию (loc/rot — мировые координаты GTA SA, Z=up).
3. **Map панель** (или **IDE / IPL / IMG** → IPL) → проверь что у объекта правильный `Model ID` в `obj.inu`.
4. **Экспорт IPL:** **IDE / IPL / IMG** → **IPL** → **Экспорт** → выбери `.ipl` файл.
5. **Map auto-split:** для больших карт включи `auto_split` toggle, `cell_size=256` — экспорт автоматически разделит на районы.
6. **gta.dat:** добавь IPL в `gta.dat` (`IPL gta3\custom\myhood.ipl`).
7. **Binary IPL:** для compiled-карт (gta_int.img) — **Экспорт** → toggle **Binary IPL** в правой панели диалога.

**Подводные камни:**
- Coordinates GTA SA: X=East, Y=North, Z=Up — Blender совпадает по умолчанию
- LOD link: lod_index в IPL — глобальный индекс (не относительный) другого объекта в том же IPL

**Панель:** View3D → Sidebar (N) → GTA Tools → Экспорт / Импорт

### DFF (Модели)

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Импорт DFF | `gtatools.import_dff` | Импорт .dff файла с мешем, материалами, UV |
| Экспорт DFF | `gtatools.export_dff` | Экспорт выделенного меша в .dff (GTA SA v3.6.0.3) |

**Экспорт включает:** геометрию, материалы, vertex colors (Day/Night), UV карты, нормали, 2DFX эффекты, BinMesh PLG.

**Авто TXD:** при импорте DFF автоматически импортирует .txd из той же папки.

> 💡 **Пример — импорт одной модели:** File → Import → GTA SA DFF → выбери `admiral.dff`. Аддон распарсит геометрию, материалы, UV. Если рядом лежит `admiral.txd` — текстуры применятся автоматически.

> 💡 **Пример — экспорт одного меша:** выдели меш → N → Экспорт / Импорт → **Экспорт DFF** → выбери путь → сохраняется с текущими материалами и vertex colors.

#### Лимиты формата DFF (uint16 / uint8)
RenderWare пакует индексы треугольников и счётчики в маленькие типы — для **одной геометрии (Atomic)** действуют жёсткие лимиты:

| Поле | Тип | Максимум |
|---|---|---|
| Вершин | u16 (индекс в `<4H>` треугольника) | 65 536 |
| Треугольников | — | 65 536 |
| Материалов | u16 (material-индекс в треугольнике) | 65 536 |
| UV-слоёв | u8 (биты 16-23 во флагах) | 255 (SA рендерит макс 2) |
| Костей в Skin PLG | u8 | 255 |

Если экспортируемый меш превышает лимит — экспорт сразу вернёт понятную ошибку, например:
```
admiral.dff: геометрия #0: 78432 вершин — RenderWare хранит индексы треугольников
в uint16 (максимум 65536 вершин). Разбей меш на части или упрости (Decimate).
```

**Обхода нет**: лимит зашит в сам формат и в движок RenderWare. Выходы — разбить меш на несколько `model_id`, либо упростить геометрию.

### COL (Коллизия)

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Импорт COL | `gtatools.import_col` | Импорт .col с типами поверхностей |
| Экспорт COL | `gtatools.export_col` | Экспорт в формате COL3 |

Экспорт автоматически центрирует объект в начало координат и записывает ID типов поверхностей.

> 💡 **Пример:** создай куб, назови `mybuilding_COL`, назначь материал с `col_mat_index = 0` (дефолтный асфальт) в Properties → Material → **COL Surface Type**. Выдели → **Экспорт COL** → получишь `mybuilding.col` с правильным материалом поверхности.

#### Лимиты формата COL (uint16)
COL2/COL3/COL4 хранит счётчики и индексы как **uint16**, поэтому **на одну модель** действуют жёсткие лимиты:

| Поле | Максимум |
|---|---|
| Вершин | 65 536 |
| Треугольников | 65 535 |
| Сфер / боксов | 65 535 каждых |
| Shadow mesh (вершин/граней) | те же лимиты |
| `model_id` в заголовке | 65 535 |

Если меш крупнее — экспорт сразу вернёт понятную ошибку вида:
```
collision.col: 'collision': 78432 треугольников — COL формат поддерживает максимум 65535.
Разбей меш на части или упрости коллизию (Decimate).
```

**Обхода нет**: лимит зашит в сам формат и в движок RenderWare. Выходы — разбить меш на несколько `model_id` или применить Decimate (для коллизий норма — до 5–10k трисов).

### TXD (Текстуры)

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Импорт TXD | `gtatools.import_txd` | Извлечение текстур и привязка к материалам |
| Экспорт TXD | `gtatools.export_txd` | Сборка текстур в .txd архив |

**Compression backend:** pure-numpy DXT-энкодер встроен в аддон (`core/dxt.py`) — векторизованный BC1/BC3, ~×7 быстрее NVTT cluster-fit на текстурах ванильного SA. Никаких внешних бинарников. В Scene properties есть селектор `gtatools_dxt_backend` для экспериментального `bpy.gpu` compute-shader варианта.

**Поддерживаемые форматы:** DXT1 (непрозрачные), DXT3 (резкая альфа), DXT5 (плавная альфа). Автоопределение по альфа-каналу.

> 💡 **Пример — быстрая сборка TXD:** меш с 3 текстурами (кирпич, окно с альфой, логотип) → выдели → **Экспорт TXD** → получишь `.txd` где кирпич DXT1, окно DXT5, логотип DXT3 — формат выбран автоматически по альфа-каналу каждой.

### Экспорт всего (Batch)

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Экспорт всего (В папку) | `gtatools.export_all` | Массовый экспорт DFF+COL+LOD+TXD |

Выделите объекты с суффиксами (`_DFF`, `_LOD`, `_COL`), нажмите Экспорт всего, выберите папку.

**Переключатели:** DFF / COL / LOD / TXD — включить/выключить каждый формат.

**Pipeline:** None / Building (Day/Night vertex colors) / Reflections (отражения на окнах).

> 💡 **Пример — экспорт здания с LOD и коллизией:** у тебя три меша `hospital_DFF`, `hospital_LOD`, `hospital_COL`. Выдели все три → **В папку** → получишь сразу 4 файла: `hospital.dff` + `hospitalLOD.dff` + `hospital.col` + `hospital.txd`. Готово к заливке в игру.

### Экспорт коллекции

Если **ничего не выделено**, Экспорт всего берёт все меш-объекты из **активной коллекции** (включая дочерние). Это позволяет экспортировать всю коллекцию без выделения.

> 💡 **Пример:** в коллекции `MyCity/Buildings` лежат 20 зданий (40 мешей — HD + LOD). Снять выделение → активировать коллекцию → **В папку** → на диске появится 40 dff + 20 txd + ... всё сразу.

Все форматы доступны через **File > Import** и **File > Export**:
- GTA SA DFF (.dff)
- GTA SA COL (.col)
- GTA SA TXD (.txd)
- GTA SA IDE (.ide)
- GTA SA IPL (.ipl)

Перетаскивание PNG/JPG/TGA из File Browser во вьюпорт автоматически создаёт материал с назначенной текстурой.

## IDE / IPL / IMG

**Панель:** View3D → Sidebar (N) → GTA Tools → IDE / IPL / IMG
**Настройки:** Properties → Scene → INU Tools → Import Map

### Импорт карты

**Шаг 1: Настройка**
- Укажите **Game Root** — папку установки GTA SA
- Выберите **Регион** (автоопределение из gta.dat: LA, SF, VEGAS, COUNTRY и т.д.)
- Оставьте **Skip 2DFX** включённым для импорта карты (по умолчанию так). Иначе каждый фонарь, корона и ped-аттрактор в районе создаст Blender-объект (Light/Empty) — тысячи штук, viewport встанет колом. Снимайте галку только когда импортируете одиночный DFF ради 2DFX-эффектов.
- Тумблер **Load COL** (по умолчанию включён) — подтягивает коллизии из кеша рядом с геометрией. Нужно для round-trip workflow (импорт части карты → редактирование → экспорт в IMG другой сборки). Выключайте если нужна только геометрия и хочется лёгкую сцену.

**Шаг 2: Извлечение ресурсов**
- Нажмите **Извлечь ресурсы** — извлечёт DFF, COL и текстуры из IMG архивов в папку `.inu_cache/` рядом с вашим .blend файлом (поэтому .blend нужно сначала сохранить)
- Текстуры декодятся в PNG параллельно (4 воркера, numpy DXT). Уже кешированные файлы пропускаются при повторном запуске
- Типичное время: ~8 секунд на один район

**Шаг 3: Импорт карты**
- Нажмите **Импорт карты** — читает DFF, PNG-текстуры и (опционально) COL **только из кеша** `.inu_cache/` (никакого обращения к IMG во время импорта)
- Если кеш пуст, оператор сообщает *«Кеш пуст — сначала запустите «Извлечь ресурсы»»* и отменяется
- DFF парсятся параллельно (4-поточный pool, numpy отпускает GIL) пока главный поток создаёт Blender-объекты — главный поток не простаивает
- COL парсятся в том же пуле. SA хранит коллизии районов в lib-файлах (`LAs.col`, `LAn.col`…) — в каждом сотни ColModel записей, поэтому карта COL ключуется по внутреннему `model_name`, не по имени файла. DFF с именем `building01` автоматически получает свой `building01` ColModel, если он есть где-либо в кешированных .col
- Объекты автоматически сортируются по коллекциям (default mode):
  - **Map_DFF_Far** — дальность прорисовки 300+
  - **Map_DFF_Mid** — дальность 100-299
  - **Map_DFF_Near** — дальность <100
  - **Map_LOD** — LOD модели (детекция по имени: `LODfoo`, `foo_LOD`, `foo1LOD`, `modeLODlaett`)
  - **Map_COL** — коллизии (создаётся лениво, только если `Load COL` включён И найдено хотя бы одно совпадение). Каждый COL-объект наследует трансформацию своего DFF-инстанса
- Тумблер **Группировать по IPL** (по умолчанию выкл) — при включении 4 баккета `Map_DFF_*` / `Map_LOD` и глобальный `Map_COL` заменяются на дерево коллекций по каждому IPL, названия совпадают с именами исходных IPL-файлов (без префикса `Map_` — round-trip остаётся читаемым, имя родителя совпадает с оригинальным IPL):
  ```
  vegasN/
    vegasN_DFF
    vegasN_LOD
    vegasN_COL
  vegasS/
    vegasS_DFF
    vegasS_LOD
    vegasS_COL
  vegasn_stream0/
    …
  ```
  Родительская коллекция скрыта во время импорта и снова показывается в конце; подколлекции создаются лениво, поэтому IPL без LOD-моделей не получит пустой `_LOD`. Полезно когда хочется:
  - Скрыть весь район одним кликом (глаз родителя — DFF, LOD и коллизии гаснут вместе)
  - Совместное редактирование карты — автор A правит `vegasN`, автор B `vegasS`, без пересечений
  - Оставлять видимым в outliner происхождение каждой модели (из какого IPL она пришла)
  - Round-trip: импорт → правка → реэкспорт через **Map Export → Разбиение: По коллекциям** восстанавливает оригинальную структуру district'ов; имя коллекции переиспользуется как basename district'а
  - Source IPL берётся как basename исходного файла (текстовые IPL — по пути файла, бинарные IPL — по имени entry в IMG архиве)
- Типичное время: ~30 секунд на район размера LA с включённым COL

**Тюнинг производительности (продвинутое):**

Включите галку **Профайлер импорта/извлечения** в *Scene → INU Tools → Performance* — в `.inu_cache/_profile.log` запишется тайминг-отчёт. Удобно посмотреть где уходит время (wall-time по стадиям, per-thread разбивка, самые медленные отдельные вызовы).

Важные стадии отчёта:
- `submit parse jobs` — одноразовая, доли секунды
- `parse wait` — сколько main thread простаивал в ожидании воркера; около нуля = воркеры идут впереди
- `parse COL files` — upfront агрегация всех .col записей в словарь `model_name → ColModel`
- `loop iter` — суммарное время внутри тела генератора (сравните с `Total wall time`; разница — overhead UI Blender'а)
- `build objects` / `build_mesh` — bpy-работа на каждый DFF
- `build COL` / `reuse COL` / `COL transform` — шаги per-model и per-instance для COL
- `reuse (copy)` — `src.copy()` для повторных инстансов
- `TXD cache load` — назначение PNG в material nodes
- `transform apply` — DFF location/rotation + inu properties

### IDE (Определения)

> **Свойства per-object:** Model ID, Draw Distance, LOD Distance, IDE Flags, Interior, LOD index — живут в **Properties → Object → "GTA SA: IDE / IPL"**. Там же показывается **проверка конфликтов ID** — если несколько объектов имеют одинаковый Model ID, аддон подсветит ошибку с именами конфликтующих объектов.

IDE файлы определяют свойства моделей: ID, словарь текстур, дальность прорисовки, флаги.

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Добавить | `gtatools.upsert_ide` | Добавить/обновить запись в IDE (авто-LOD) |
| Удалить | `gtatools.remove_ide` | Удалить запись по Model ID |
| Импорт | `gtatools.import_ide` | Загрузить определения → применить к объектам |
| Экспорт | `gtatools.export_ide` | Записать выделенные объекты в IDE файл |

**Все секции:** objs, tobj, anim, cars, peds, weap, hier, txdp.

**Авто-LOD:** при добавлении пары DFF+LOD автоматически назначаются:
- **Model ID:** LOD = DFF ID + 1 (например DFF ID 3500 → LOD ID 3501)
- **Draw Distance:** LOD = 999 (максимальная видимость). HD модель видна до своей дальности (например 299м), после чего появляется LOD и виден до 999м
- **TXD:** LOD использует тот же словарь текстур что и DFF

> 💡 **Пример — добавить здание в mymap.ide:** выдели `building01_DFF` и `building01_LOD` → в Object Properties → **INU Tools: Model** поставь `Model ID = 3500` на DFF → N → IDE / IPL / IMG → секция IDE → укажи путь к `mymap.ide` → **Добавить**. В файл запишется две строки: `3500, building01, building01, 299` и `3501, LODbuilding01, building01, 999`.

**Флаги IDE** (15 чекбоксов в свойствах объекта):

| Флаг | Бит | Описание |
|------|-----|----------|
| IS_ROAD | 1 | Дорога |
| DRAW_LAST | 4 | Прозрачный, рисовать последним |
| ADDITIVE | 8 | Аддитивный блендинг |
| NO_ZBUFFER_WRITE | 64 | Не писать в Z-буфер |
| NO_SHADOWS | 128 | Не получать тени |
| GLASS_TYPE_1 | 512 | Разбиваемое стекло |
| GLASS_TYPE_2 | 1024 | Стекло с трещинами |
| GARAGE_DOOR | 2048 | Дверь гаража |
| DAMAGABLE | 4096 | Разрушаемый |
| IS_TREE | 8192 | Дерево, качается на ветру |
| IS_PALM | 16384 | Пальма, качается на ветру |
| NO_FLYER_COL | 32768 | Нет коллизии с летающим |
| IS_TAG | 1048576 | Граффити тег |
| NO_BACKFACE_CULL | 2097152 | Рисовать обе стороны |
| BREAKABLE_STATUE | 4194304 | Разрушаемая статуя |

### IPL (Размещение)

IPL файлы определяют позиции, повороты и связи LOD объектов на карте.

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Добавить | `gtatools.upsert_ipl` | Добавить/обновить размещение (авто-LOD привязка) |
| Удалить | `gtatools.remove_ipl` | Удалить по Model ID. При удалении записи из середины файла все LOD индексы остальных объектов автоматически пересчитываются — иначе игра будет ссылаться на неправильные строки и может вылететь |
| Импорт | `gtatools.import_ipl` | Расставить объекты или создать Empty |
| Экспорт | `gtatools.export_ipl` | Записать выделенные объекты с мировыми трансформами |

**Конвертация кватернионов:** GTA SA хранит (X,Y,Z,W) сопряжённый, Blender использует (W,X,Y,Z). Конвертация автоматическая.

**Бинарный IPL:** файлы с заголовком `bnry` (внутри IMG архивов) читаются автоматически.

> 💡 **Пример — расставить модель на карте:** импортировал `building01.dff`, назначил ему Model ID 3500. Двигай/поворачивай как хочешь в сцене → IPL → **Экспорт** → выбери `mymap.ipl` → в файл запишется строка `3500, building01, 0, X, Y, Z, QX, QY, QZ, QW, lod` с реальными мировыми координатами.

### IMG Архив

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Импорт из IMG | `gtatools.import_from_img` | Извлечь и импортировать модели по IDE/IPL |
| Экспорт в IMG | `gtatools.export_to_img` | Упаковать DFF+COL+LOD+TXD в .img архив |

**Тумблеры экспорта (единые с «В папку»):** DFF / COL / LOD / TXD — что упаковывать. И Unified Export панель (N-sidebar), и IDE/IPL/IMG панель пишут в одни и те же scene-свойства, так что видимые тумблеры всегда применяются к тому оператору, который ты нажал.

**Опции импорта:** Skip LOD / Загрузить TXD / Загрузить COL.

**COL Library режим** (виден когда **COL** включён) — тумблер + поле имени. Все коллизии пакуются в один multi-entry `.col` файл (например `collision.col`) вместо одного `.col` на модель. Каждая запись хранит свой `model_id`; игра сопоставляет COL с DFF по ID. Так ваниль хранит `LAs.col` / `LAn.col` и другие.

**Shared TXD режим** (виден когда **TXD** включён) — тумблер + поле имени, симметрично с COL Library. Пакует **все** текстуры всех экспортируемых DFF/LOD в один общий `.txd` (по умолчанию `textures.txd`). Удобно для районов и сборок где множество моделей делят одни и те же текстуры — уменьшает количество TXD и чище структура IMG.

**Batch writer + параллельное кодирование (большие экспорты):** `Экспорт в IMG` открывает архив **один раз**, дописывает каждый новый байт-блок последовательно, и переписывает директорию **ровно один раз** в конце — а не на каждый файл. Плюс сериализация DFF и COL (`to_bytes()` / `write_col()`) идёт в 4-поточном `ThreadPoolExecutor` (numpy/zlib отпускают GIL). Для полного района это заменяет ~3000 переписываний директории (~2.6 ГБ лишних записей) одним, плюс ~4× ускорение CPU-bound кодирования — суммарно **5–15× end-to-end**.

> 💡 **Пример — пакетный залив в gta3.img:** у тебя 50 домов готовых к экспорту. Укажи путь `gta3.img` в Import Map settings → выдели дома → **Экспорт в IMG** → откроется диалог с UIList где видно TXD-имена всех моделей (редактируемые). Опционально включи Shared TXD если они делят текстуры. Нажал OK — все DFF+COL+LOD+TXD закодируются параллельно и запишутся в архив. После этого обязательно **Rebuild Archive** в IMG-туле (иначе в игре останутся старые версии).

### BBox режим

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| BBox: ON/OFF | `gtatools.toggle_bbox` | Переключить отображение Bounding Box |

При включении все объекты Map_ коллекций переключаются в `BOUNDS`. Объекты в радиусе 300м от выделенного остаются `TEXTURED`. Обновляется автоматически при смене выделения.

> 💡 **Пример:** импортировал карту LA (5000+ объектов), Blender тормозит на отрисовке. Включи **BBox: ON** → вокруг далёких домов только кубики-рамки, рядом с выделенным твоим объектом (в радиусе 300м) — полноценные текстуры. Viewport летает.

### Суффиксы / Префиксы

**Панель:** N-sidebar (`N`) → GTA Tools → **Экспорт / Импорт** → ▸ Суффиксы / Префиксы *(свёртываемая секция, как DFF Flags)*

Определяют как аддон распознаёт тип модели по имени объекта в Blender.

**Суффиксы** (в конце имени):
- DFF: `_DFF` → `mybuilding_DFF` определяется как DFF модель
- LOD: `_LOD` → `mybuilding_LOD` определяется как LOD модель
- COL: `_COL` → `mybuilding_COL` определяется как коллизия

**Префиксы** (в начале имени):
- LOD: `LOD` → `LODmybuilding` определяется как LOD модель

Можно использовать **либо суффикс, либо префикс** для каждого типа — не оба одновременно. При вводе одного второй автоматически очищается. Если ни суффикса ни префикса нет — модель считается DFF.

При экспорте IDE/IPL LOD модель всегда записывается с префиксом `LOD` перед именем (формат GTA SA).

> 💡 **Пример — сменить конвенцию проекта:** твой старый проект использует суффиксы `_DFF`/`_LOD`/`_COL`, а новый коллега работает с префиксами `LOD` и без суффиксов DFF. Открой Суффиксы/Префиксы в Export-панели → очисти `Суффикс DFF` и `Суффикс LOD` → впиши `LOD` в **Префикс LOD**. Все объекты в сцене теперь распознаются по новой конвенции без переименования (проверить: Object Properties → INU Tools: Model → «По имени: ...»).

### Определение LOD

В vanilla GTA SA и инструментах Rockstar LOD-модели именуются разными способами — не только стандартным префиксом `LOD<name>`. При импорте карт INU Tools определяет LOD двухслойным подходом:

**Слой 1 (надёжный) — ссылки IPL.** В каждой строке IPL `inst` есть поле `lod_index`, указывающее номер строки LOD-напарника в том же файле. Любой инстанс, на который кто-то ссылается, автоматически помечается как LOD вне зависимости от имени файла. Это 100% надёжно для корректно собранных карт.

**Слой 2 (fallback) — эвристика по имени.** Для одиночного импорта, битых IPL или операций в сцене, где IPL-контекста нет, аддон ловит такие паттерны:

| Имя | LOD? | Срезается до | Почему |
|---|---|---|---|
| `LOD_foo` | ✅ | `foo` | префикс + ведущий `_` удаляется |
| `LODfoo`, `lodfoo` | ✅ | `foo` | префикс без разделителя |
| `foo_LOD`, `foo_lod` | ✅ | `foo` | суффикс `_LOD` срезается целиком |
| `tatar_str_1LOD` | ✅ | `tatar_str_1` | bare-суффикс рядом с цифрой |
| **`modeLODlaett`** | ✅ | `modelaett` | заглавный `LOD` в середине с lowercase-соседом (legacy-стиль Rockstar) |
| **`foo_LOD_bar`** | ❌ | — | `LOD` окружён `_` с обеих сторон → считается отдельным токеном в середине |
| **`bar_LOD_baz_LOD_qux`** | ❌ | — | то же самое — каждое вхождение между сепараторами |
| `CLOD`, `FLOOD` | ❌ | — | всё заглавное, нет lowercase-соседа |
| `explode`, `clodmock` | ❌ | — | нет заглавного `LOD` (case-sensitive проверка) |

**Детали embedded-правила.** Детектор ищет `LOD` с учётом регистра (именно заглавные буквы). Срабатывает только если хотя бы один из соседних символов — lowercase. Поэтому `modeLODlaett` (соседи `e`/`l` строчные) распознаётся как LOD, а `foo_LOD_bar` (оба соседа — `_`) — нет. Это соответствует легаси-паттерну Rockstar, где `LOD` вставлялся прямо в середину базового имени (база `modelaett` → LOD `modeLODlaett`), и при этом не ловит ложных срабатываний на именах, где `_LOD_` — литеральный токен.

**Где применяется.** Логика срезки используется при переименовании во время импорта карты, `Replace IPL Placeholders`, распределении по коллекциям и сопоставлении пар COL/DFF. Правильно определённое базовое имя позволяет импорту отправлять модель в `Map_LOD` вместо `Map_DFF_*` и даёт утилитам парных объектов находить HD-близнеца.

> Реализация: `is_lod_name()` и `strip_lod_marker()` в [core/ipl.py](INU_tools/core/ipl.py).

**Панель:** N-sidebar (`N`) → GTA Tools → **ID Manager** *(отдельная подпанель в DATA-зоне)*

- Показывает количество свободных/занятых ID
- **Следующий свободный ID**
- **Назначить ID** — следующий свободный ID выделенным объектам

Переключил пресет обратно на `default` — вернулась прежняя база ID.

## Материалы

### Эффекты материалов GTA SA

**Панель:** Properties → Material → GTA SA Material Effects

| Свойство | Описание |
|----------|----------|
| Environment Map | Текстура отражения с коэффициентом (0-1) |
| Bump Map | Текстура нормалей |
| Reflection | Зеркальное отражение с масштабом, смещением, интенсивностью |
| Specular | Блик с уровнем и текстурой |
| Dual Texture | Вторая текстура с режимами смешивания (11 вариантов Src/Dst) |
| UV Animation | Анимированная прокрутка UV с именем анимации |

> 💡 **Пример — окно здания с отражениями:** создай материал `building_window` → включи ☑ Environment Map → укажи текстуру `xenvmap`, коэффициент `0.6` → в игре окно отразит небо/облака плывущие над городом. Для прозрачного стекла дополнительно включи FB Alpha.

### Пресеты GTA Material

**Панель:** Properties → Material → **GTA Material** → Preset

Быстрое применение типовых настроек к материалу одним кликом. Вместо ручной настройки 25+ полей `mat.inu.*` (env map, specular, reflection, dual texture и т.д.) — выбрал из dropdown, нажал ✓ Apply.

#### Встроенные пресеты (идут с аддоном)

| Пресет | Что настраивает |
|---|---|
| **Generic** | Сбрасывает все эффекты — чистый текстурированный материал |
| **Vehicle Body** | Кузов машины: env map (`xvehicleenv128`, коэф 0.2) + specular (`vehiclespecdot64`) + reflection 0.05 |
| **Vehicle Glass** | Стекло машины: env map с FB alpha, коэф 0.4 |
| **Ped / Skinned** | Обычный скиннед материал (для персонажей) |
| **Env Mapped** | Только env map (`xenvmap`, коэф 0.5) без specular/reflection |
| **Dual Texture** | Включает вторую текстуру с alpha blend (src/dst = SRCALPHA / INVSRCALPHA) |
| **Specular** | Базовый specular с уровнем 1.0 |

Эти пресеты всегда в dropdown, удалить нельзя.

#### Пользовательские пресеты

Хранятся **снаружи аддона** — в `<blender addons dir>/INU_Preset/material_presets/*.json`. При обновлении или переустановке аддона они не пропадают. Рядом с `INU_Preset/id_presets/` (тот же корень что у пресетов ID-менеджера).

#### Пример использования — моделишь машину

Допустим, у тебя машина с 15 материалами: кузов, стёкла, хром, фары, шины, интерьер. Ручная настройка каждого = 7 полей × 15 = 105 кликов.

**Шаг 1.** Выдели материал кузова в стеке материалов объекта.

**Шаг 2.** Properties → Material → **GTA Material** → Preset → выбери `Vehicle Body` → нажми ✓ (Apply). Все поля проставились: env map, specular, reflection.

**Шаг 3.** Переключись на материал стёкол → `Vehicle Glass` → ✓. Готово.

**Шаг 4.** Допусти ты нашёл свою идеальную настройку для «кузова под ретро-сан-андреас» — с сильнее матовым специкулем. Выбери этот материал → Preset → **Сохранить как…** → имя: `car_retro_matte`, описание: `матовый кузов для старых машин`. Save.

Теперь в папке `<addons>/INU_Preset/material_presets/` появился `car_retro_matte.json`:
```json
{
  "name": "car_retro_matte",
  "description": "матовый кузов для старых машин",
  "mat_inu": {
    "ambient": 1.0,
    "export_env_map": true,
    "env_map_tex": "xvehicleenv128",
    "env_map_coef": 0.15,
    "export_specular": true,
    "specular_level": 0.4,
    "specular_texture": "vehiclespecdot64",
    "export_reflection": true,
    "reflection_intensity": 0.02
  }
}
```

**Шаг 5.** Перезагрузка dropdown не нужна — пресет появится сразу. При открытии другого материала в списке будет `car_retro_matte`. Применяется в 1 клик.

**Шаг 6 (бонус).** Скопируй JSON-файл другу → он кладёт себе в `<addons>/INU_Preset/material_presets/` → у него такой же пресет. Можно шарить между членами моддинг-команды.

#### Что сохраняется в пресет

25 полей из `INUMaterialProps`:
- **Ambient:** `ambient`
- **Env Map:** `export_env_map`, `env_map_tex`, `env_map_coef`, `env_map_fb_alpha`
- **Bump:** `export_bump_map`, `bump_map_tex`
- **Reflection:** `export_reflection` + 5 полей (scale X/Y, offset X/Y, intensity)
- **Specular:** `export_specular`, `specular_level`, `specular_texture`
- **Dual Texture:** `export_dual_tex`, `dual_tex_src_blend`, `dual_tex_dst_blend`, `dual_tex_texture`
- **UV Animation:** `export_animation`, `animation_name`

**Не сохраняется** (специфично для конкретного материала, не переносимо):
- `vehicle_color_slot` — per-instance carcols-метка
- `col_*` — collision surface (отдельная панель COL Surface Type)
- `uv_anim_*` runtime параметры (speed_u/v, duration)

#### Удаление пресета

Выбери пользовательский пресет в dropdown → кнопка **Удалить** становится активной → Delete. Файл удалён. Встроенные пресеты (Generic/Vehicle/…) удалить нельзя — кнопка отключается.

**Панель:** Properties → Material → COL Surface Type

179 типов поверхностей GTA SA в 13 категориях. Выпадающий список с поиском. Каждая поверхность имеет:

- Флаги, Яркость, Свет

### Текстуры

**Панель:** Properties → Scene → INU Tools → Текстуры

- **Системные текстуры** — путь к общей папке с текстурами (например `System_textures` от MTA/GTA)

## Прелайт (Vertex Colors)

> **Важное в 1.6.3:** запекание теперь учитывает **smooth/flat shading** (использует `loop.normal` вместо `poly.normal`). Также **скрытые лампы** (через 👁 viewport, 📷 render или скрытая коллекция) **пропускаются** при запекании — раньше брались все point lights в сцене.


**Панель:** View3D → Sidebar (N) → GTA Tools → Prelight

### Запекание

1. **Создать Day/Night** — создаёт атрибуты `Day` и `Night`
2. **Создать 8 ламп** — расставляет 8 точечных источников вокруг объекта
3. **Bake** (Fast) — быстрое запекание на CPU без теней
4. **Bake с тенями** — запекание с raycast тенями через depsgraph

**Настройки:**
- Ambient (0-1) — базовая яркость
- Intensity (0-1) — сила света
- Gamma (0.5-3.0) — гамма-коррекция
- Тени — вкл/выкл

> 💡 **Пример — прелайт дома для карты:** выдели меш здания → Prelight → **Создать Day/Night** → **Создать 8 ламп** (вокруг объекта автоматически встают 8 point-светильников) → включи ☑ Тени → **Bake с тенями**. Атрибут `Day` заполняется освещённостью с мягкими тенями. Потом тот же процесс для Night (обычно уменьшаешь Intensity до 0.3 и меняешь цвет ламп на синеватый) — переключись на атрибут Night перед Bake.

### Заливка цветом

Покраска выделенных полигонов выбранным цветом. Поддержка уровней (слоёв заливки) и отмены.

> 💡 **Пример:** хочешь оттенить крышу здания ярче стен. Вход в Edit Mode → выдели полигоны крыши → в Prelight → **Заливка цветом** → цвет = RGB(1,1,0.9) → Apply. Стены остались как были, крыша подсветилась жёлтым. Не понравилось — **Откат (Undo fill)** вернёт предыдущий уровень.

### Рассеивание света

Распространение света от выделенных полигонов наружу. Параметры:
- Интенсивность, Затухание, Радиус, Итерации

> 💡 **Пример — светящийся неон:** выдели грани неоновой вывески → Заливка цветом розовым → **Рассеять от выделенных** (Интенсивность 0.8, Радиус 2м, Итерации 3) → соседние грани вокруг вывески получают розоватый оттенок, имитируя свечение неона на стене здания.

### Рассеять цвет

**Sub-panel:** Prelight → Инструменты → Рассеять цвет

Заливает выбранный цвет **вокруг** выделенных полигонов (в отличие от *Рассеивания света* которое перераспределяет уже существующий прелайт). Полезно когда нужно мягко затонировать соседнюю геометрию — отражения от неона, акценты под прожекторами, грязь вокруг люка.

**Параметры:**
- *Сила* (0–1) — насыщенность выбранного цвета в центре (1 = полностью заменить vcols в выделенных вершинах).
- *Дальность* (0–1) — радиус как доля половины bbox-диагонали меша. 0 = только выделенные вершины; 1 = falloff покрывает половину диагонали.
- *Цвет* — берётся из активной кисти **Vertex Paint** (workflow покраски остаётся единым). При отсутствии кисти — fallback на scene color picker.

Падение интенсивности линейное по KDTree-расстоянию — чем дальше вершина от любого выделенного полигона, тем меньше она получит цвета.

### Пост-обработка

| Инструмент | Описание |
|-----------|----------|
| Smooth | Сглаживание цветов между соседними вершинами |
| Smooth между объектами | Сглаживание на стыках разных мешей |
| Contrast | Настройка контраста |
| Brightness | Настройка яркости |
| Gamma | Гамма-коррекция |

> 💡 **Пример — стык двух домов:** два соседних здания стоят вплотную. Запёк прелайт на каждом отдельно — видны резкие швы в цвете vertex colors на границе. Выдели оба → **Smooth между объектами** (проходы 2, сила 0.5) → градиент плавно перетекает между мешами, шов исчезает.

### COL Light

**Панель:** View3D → Sidebar (N) → GTA Tools → Prelight COL

Конвертация vertex colors в COL Day/Night Light значения (0-15). Авторазбиение материалов по яркости.

- **Preview** — визуализация значений света на меше
- **Bake** — запись значений в свойства COL материалов
- **Диапазоны Day/Night** — настраиваемые пороги

> 💡 **Пример — свет для коллизии тоннеля:** у тебя COL-меш тоннеля с vertex colors где центр тёмный, края светлее. Открой Prelight COL → **👁 Preview** — меш раскрасится цифрами 0-15. Настрой диапазон Day (min=0, max=6) чтобы центр был 0 (тёмный) а вход 6 (светлее) → **Запечь COL Light** → материалы получают соответствующие Day/Night Light значения. В игре машина при въезде в тоннель будет автоматически затемняться.

### Пресеты

**Шапка** в верху панели Prelight — селектор пресета + 4 кнопки.

Хранятся как `.json` в папке `INU_Preset/`. Один пресет фиксирует всё связанное с прелайтом во всей панели и её sub-панелях:
- **Запекание** — Ambient, Intensity, Gamma, Shadows
- **Modulate Color** — режим (OFF/Day/Night), mix, contrast, gamma
- **Adjust Color** — V-offset
- **Рассеять цвет** — strength, distance
- **Пост-обработка** — smooth iterations/factor, contrast, brightness, gamma
- **Per-object Day/Night** — V-offset для каждого атрибута + флаг auto-create Day/Night атрибутов при Load

| Кнопка | Действие |
|---|---|
| ✓ | **Сохранить в выбранный пресет** — перезаписывает текущий пресет из dropdown'а текущими значениями сцены. В status bar показывается diff: какие поля изменились (`old → new`) и какие добавились. Без диалога имени. |
| ⬇ Load | Подтягивает значения пресета в сцену + активный меш (создаёт Day/Night атрибуты если пресет это требует). |
| + Save | Создать НОВЫЙ пресет (открывает диалог имени). |
| − Delete | Удалить выбранный пресет. |

> 💡 **Workflow на примере:** настроил ночной look — Modulate Color = Night, Day V = +30, Night V = −20 → **+ Save** → имя `my_night`. Поправил Modulate Mix с 0.002 на 0.005 → **✓** перезаписывает `my_night`, status bar пишет `modulate_mix: 0.002 → 0.005`. Перешёл в другую сцену → выбрал `my_night` → **⬇ Load** → все настройки восстановлены на каком бы меше ты ни работал.

### Настройка цвета (V-offset на атрибут)

В каждом ряду селектора Day/Night атрибутов — свой слайдер V-offset:

```
[Day]    V: +30.0   [-]
[Night]  V: -20.0   [-]
```

Введи значение → нажми Enter → яркость **немедленно** применится к этому атрибуту vertex colors (только на этом объекте). Значение сохраняется per-object и переживает повторное запекание — после нового bake offset автоматически переприменяется к свежим колорам.

### Управление Vertex Colors

| Кнопка | Описание |
|--------|----------|
| Создать Day/Night | Создаёт оба атрибута `Day` и `Night` |
| Day + / Night + | Создать отдельный атрибут |
| Day - / Night - | Удалить отдельный атрибут |
| Превью | Включить/выключить визуализацию Day/Night микса |
| Добавить LightMap | Загрузить текстуру лайтмапа и подключить на UV2 (Multiply) |
| 👁 LightMap | Включить/выключить отображение лайтмапа (mute/unmute) |
| ➖ LightMap | Удалить лайтмап ноды из материалов |
| Анализ | Показать гистограмму vertex colors (min/max/avg) |
| Сброс | Сбросить настройки запекания |

**Режимы Edit/Paint:** кнопки переключения между Object, Edit и Vertex Paint режимами.

> 💡 **Пример — скопировать дневной прелайт как ночной (быстрый старт ночного):** ты запёк только `Day` атрибут → **Day → Night** → `Night` создаётся как копия `Day`. Теперь открой Post-Processing → **Brightness** = −0.3 → применить к Night → получил затемнённую версию дневного. Дальше доводишь руками (добавить заливку желтым вокруг фонарей и т.д.).

### Слои Vertex Color (BETA)

**Секция:** Prelight panel → ▸ **Слои Vertex Color (BETA)** (collapsible, между LightMap и Запекание)

Photoshop-стайл **неразрушающее** редактирование vertex colors. Стопка именованных слоёв на каждый scope (Day / Night), у каждого свой opacity / blend mode / brightness / contrast. Композит автоматически пишется в `Day` / `Night` — для live preview во вьюпорте И при экспорте DFF. Сами слои остаются доступны для редактирования в .blend.

**Зачем нужно:**
- Добавить зелёный налёт на стены не пере-запекая освещение
- Накрасить свечение окон поверх Itera-бейка
- Подкрутить только тени в одной зоне, не трогая остальное
- Попробовать вариант цвета, откатить одним слайдером

**Хранение:** каждый слой = `BYTE_COLOR` color attribute на меше, имя `VCL_D_<label>` (Day-стек) или `VCL_N_<label>` (Night-стек). Лимит **10 слоёв на стек**. Видны в списке Color Attributes под секцией «Дополнительные атрибуты» — слои это полноценные данные, рисуются стандартным Blender Vertex Paint mode.

#### Пайплайн (типовой workflow)

1. **Создай `Day` / `Night`** — уже есть из бейка, или через обычные кнопки Day/Night выше
2. **Добавь слой** — клик [+] в «Слои Day» — создаётся `VCL_D_Layer_1`, полностью прозрачный
3. **Покрась слой** — клик **Рисовать** на активной строке слоя → войдёшь в Vertex Paint на `VCL_D_Layer_1`
4. **Подкрути слой** — крути Opacity / Blend Mode / Brightness / Contrast у активного
5. **Включи Live Preview** → атрибут `Day` теперь показывает композицию (база + все видимые Day-слои)
6. **Экспортируй DFF** — композит auto-flatten'ится в `Day` / `Night` на время экспорта; слои в .blend остаются нетронутыми

#### Кнопки

| Кнопка | Описание |
|--------|----------|
| **▸ Слои Vertex Color (BETA)** | Развернуть / свернуть секцию |
| **Live preview** (toggle) | Угнать `Day` / `Night` под композицию. ON: оригиналы бэкапятся в custom-prop, композит пишется в `Day` / `Night` живьём. OFF: оригиналы восстанавливаются |
| **↻** | Пересобрать композит вручную (при включённом Live Preview) |
| **☀ Day** / **🌙 Night** | Переключить активный color attribute на `Day` или `Night` (там и есть композит при Live Preview ON). Текущая зажата (depress) |
| Список «Дополнительные атрибуты» | Все color attributes кроме Day/Night (VCL слои, custom прилайт). Radio = активировать, ❌ = удалить |
| **Слои Day** [+] | Создать Day-слой (лимит 10) |
| **Слои Day** [−] | Удалить активный слой и его атрибут |
| **Слои Day** [▲] [▼] | Поменять порядок слоя в стеке (это меняет порядок блендинга) |
| Per-row [☑] | Multi-select для групповых правок |
| Per-row [👁] | Видимость — выключенный исключается из композита (alpha → 0) |
| Per-row [🔒] | Лок paint — слайдеры всё ещё работают, но Vertex Paint не пишет |
| Per-row label | Клик по тексту = переименовать (атрибут на меше тоже переименуется) |
| Per-row opacity slider | 0–1 прозрачность слоя в композите |
| **Режим** | Blend mode: Нормаль / Умножение / Добавить / Вычесть |
| **Яркость до** | Сдвиг яркости пикселей слоя ДО блендинга (−1..+1) |
| **Контраст до** | Контраст пикселей слоя ДО блендинга, относительно 0.5 (0..3) |
| **Рисовать** | Активировать атрибут этого слоя + войти в Vertex Paint |
| **→ База** | Превратить VCL-слой в обычный color attribute (убирает VCL префикс) |
| Multi-edit footer (Absolute / Relative) | Групповые слайдеры на все выделенные (☑) слои |
| **Перекрасить выделенные…** | Заменить RGB всех окрашенных пикселей выделенных слоёв на выбранный цвет (alpha не трогается) |

#### Детали Live Preview

- **ON:** атрибуты `Day` (и `Night`) перезаписываются композицией стека. Оригинал лежит в `mesh["_vcl_backup_day"]` / `mesh["_vcl_backup_night"]` как base64-encoded float-буфер
- **OFF:** оригиналы восстанавливаются из бэкапа; backup custom props удаляются
- Композит пересчитывается при: любом слайдере слоя, ▲/▼ перемещении, add/remove/promote/demote, мазке кистью (depsgraph хук замечает когда active = `VCL_*`)
- Recompose дебаунсится ~100 мс через one-shot `bpy.app.timers` — быстрый драг слайдера = один финальный композит, а не 50

> ⚠ **Не рисуй напрямую на `Day` / `Night` пока Live Preview ON.** Эти атрибуты держат композицию; твой мазок сотрётся на следующем recompose. Рисуй на слое — клик **Рисовать** на строке слоя.

#### Auto-flatten при экспорте

DFF-экспортёр оборачивает `build_dff_clump` в context manager:
1. Снимает snapshot `Day` / `Night` в память
2. Композитит Day-стек в `Day`, Night-стек в `Night`
3. DFF-writer читает композит → пишет в файл
4. Восстанавливает `Day` / `Night` из snapshot

Итог: .blend выглядит ровно как до экспорта, а .dff содержит финальный композит. Без ручного «commit».

> 💡 **Пример — тестим вариант цвета для зелёной крыши:** у тебя здание с запечённым `Day`. Добавляешь Day-слой `green_roof`, красишь крышу зелёным, opacity 0.6, blend Normal. Live Preview ON → видишь композит. Экспорт DFF, тестим в игре. Не нравится — обратно в Blender, opacity до 0.3, re-export. Совсем не нравится — `[−]` удаляет слой; `Day` сам собой остаётся в исходном бейке.

## 2DFX Эффекты

**Панель:** View3D → Sidebar (N) → GTA Tools → 2DFX Effects

Создание и настройка 2DFX эффектов, экспортируемых в DFF файлы.

**Типы эффектов:**
- **Light** — уличные фонари, неон, короны
- **Particle** — дым, огонь
- **Ped Attractor** — банкомат, скамейка, остановка
- **Sun Glare** — отражение солнца на поверхности

### Свойства света

| Свойство | Варианты |
|----------|---------|
| Пресеты | Default, OnAllDay, Lamp Post, Lamp Post Coast, BB Pickup, Flashing (3 типа), Train Crossing, Traffic |
| Текстура короны | 34 текстуры (coronastar, coronamoon, headlight и др.) |
| Текстура тени | 13 текстур (shad_exp, shad_car, lamp_shad_64 и др.) |
| Режим показа | Default, Random Flashing, Flash Rain, Only Rain, No Rain |
| Тип бликов | None, Type 1-3 |
| Цвет | RGBA палитра |
| Размер короны | Float |
| Дальность прорисовки | Float |
| Дальность света | Float |
| Размер тени | Float |
| Флаги 1/2 | Integer |

**Привязка к модели:** родительство Empty к мешу. Координаты автоматически пересчитываются при экспорте.

**Detach All from Mesh:** массовое отвязывание всех 2DFX от выделенного меша. В UI меша показывается список всех привязанных 2DFX с кнопками индивидуальной отвязки.

**Превью:** визуализация короны/тени в реальном времени во вьюпорте. Billboard tracking реализован через **draw handler** *(1.6.3)* — стабильно работает при переключении между сценами.

> 💡 **Пример — уличный фонарь:** выдели меш столба фонаря → 2DFX → **Create Light** → появится Empty с дефолтной лампой. Переведи Empty на вершину столба → выбери Preset **Lamp Post** → ✓ Apply (проставит жёлтый цвет, текстуру coronastar, дальность 200м). Родительство к мешу автоматическое → Empty.parent = столб. При экспорте DFF координаты 2DFX пишутся относительно меша.

> 💡 **Пример — мигающая красная авария:** Create Light → Preset **Flashing (Maverick1)** → ✓ Apply → Show Mode `1 RANDOM_FLASHING` автоматически. В игре эта корона будет случайно мигать красным — идеально для аварийных сигналов или проблесковых маячков.

## Particle Effects (effects.fxp)

Полноценный редактор GTA SA `effects.fxp` — текстового файла с **82 системами частиц** (огонь, дым, кровь, искры, вода, гильзы и т.д.), которые движок проигрывает когда в зоне видимости появляется объект с `Particle` 2DFX-меткой.

**Расположение файла:** `<game_root>/models/effects.fxp` — резолвится из `gtatools_game_root` Scene property.

### 1. Настройка сцены

Укажи **Game Root** в **N-sidebar → GTA Tools → Import Map** (раскрывающийся блок). Dropdown доступных эффектов заполняется из `<game_root>/models/effects.fxp`:

- Файл парсится один раз при первом открытии dropdown и кэшируется (ключ = путь + mtime); пере-парсится автоматически при сохранении новой системы.
- Если Game Root пустой или `effects.fxp` отсутствует — dropdown покажет `<Game Root не задан>` / `<effects.fxp не найден>`.
- Используй **Reload effects.fxp** оператор если редактировал файл вручную вне Blender.

### 2. Привязка частицы к модели

Эффект частицы привязывается к мешу через дочерний **Empty** с 2DFX-меткой `Particle`.

1. Открой **N-sidebar → GTA Tools → 2DFX Effects** (или 2DFX **floater** через иконку 🪟).
2. **Создать эффект ▾ → Частица** — Empty создаётся в позиции 3D-курсора с `effect_2dfx = 'PARTICLE'`.
3. С выбранным Empty открой **Properties → Object → INU Tools: Model** → найди dropdown **Particle Effect**. Выбери имя системы (`prt_blood`, `prt_fire_med`, `prt_smoke_huge` и т.д.).
4. **Привязать к модели:**
   - Выдели DFF меш к которому хочешь привязать эффект.
   - **Shift-клик по particle Empty** — Empty становится active object (Empty активный + меш в выделении).
   - В 2DFX панели жми **Привязать к модели** (`gtatools.attach_2dfx`).
   - Empty становится child'ом меша, world-позиция сохраняется.

Если позже надо разорвать связь — жми **Отвязать от модели** (один эффект) или **Отвязать все от меша** (batch-unparent всех 2DFX-child'ов выделенного меша).

Empty теперь ссылается на систему в `effects.fxp`. Его локальная трансформа относительно parent-меша = точка спавна + ориентация эмиссии в локальном пространстве модели.

### 3. Редактирование эмиттера

Когда particle Empty активен, **Properties → Object → INU Particle Properties** выставляет полный набор параметров:

**Спрайт и смешивание**

| Свойство | Default | Описание |
|---|---|---|
| `Texture` | от системы | Имя спрайта в `particle.txd` (`sphere`, `smoke3`, `flame`) |
| `SrcBlend` | 4 | D3D9 source blend factor (`4`=SrcAlpha для alpha-blended, `2`=One для чистого additive) |
| `DstBlend` | 5 | D3D9 destination blend factor (`5`=InvSrcAlpha) |

> **Типовые рецепты blend:** SrcAlpha + InvSrcAlpha = alpha-blended спрайт (дым, кровь). One + One = аддитивное смешение (огонь, magic glow). One + InvSrcAlpha = pre-multiplied alpha.

**Цвета по времени жизни**

- `color_start` — RGBA при рождении (time = 0)
- `color_end` — RGBA при смерти (time = 1)
- `color_mid_enabled` + `color_mid` + `color_mid_time` — опциональная третья точка для 3-stop интерполяции (например для огня: жёлтый → красно-оранжевый → чёрный)

**Размер**

- `size_start` — размер частицы при рождении (world units)
- `size_end` — при смерти

**Эмиссия**

| Свойство | Описание |
|---|---|
| `life` | Длительность жизни частицы в секундах (1.5 для дыма, 0.3 для искр) |
| `life_bias` | ± случайное отклонение от base life |
| `rate` | Частиц в секунду |
| `speed` | Начальная скорость (units/sec) |
| `speed_bias` | ± случайное отклонение |
| `direction` | Вектор направления эмиссии (XYZ, нормализованный) |
| `angle_min` / `angle_max` | Угол конуса разброса (радианы, 0 = лазер, π = полная сфера) |
| `volume` (XYZ extents) | Объём спавна вокруг origin |
| `volume_radius` | Радиус сферы спавна (переопределяет box когда > 0) |
| `volume_min` | Внутренний box (annular spawn для эффектов колец) |
| `offset` | Смещение точки спавна от origin эмиттера |
| `rotation_min` / `rotation_max` | Начальное вращение спрайта (радианы) |
| `rotspeed_min` / `rotspeed_max` | Скорость вращения спрайта |

**Физика**

| Свойство | Описание |
|---|---|
| `force` | Постоянный вектор силы (гравитация сюда, например `(0, 0, -9.8)`) |
| `friction` | Демпфирование скорости (1.0 = без трения, 0.5 = сильное сопротивление) |
| `wind` | Множитель ветра движка (0 = без ветра, 1 = полное сцепление) |
| `noise` | Магнитуда Perlin-noise turbulence |
| `jitter` | Per-frame случайное дрожание (отличается от noise — jitter некоррелирован) |
| `ground_bounce` | Отскок от земли (0 = проходит насквозь, 1 = полный отскок) |
| `ground_speedmult` | Множитель скорости после отскока |

**Система (для всего эффекта, не per-emitter)**

| Свойство | Описание |
|---|---|
| `sys_length` | Длительность всей системы в секундах (0 = бесконечно, например для огня) |
| `sys_playmode` | Режим воспроизведения: 0 = once, 1 = loop, 2 = one-shot burst, 3 = continuous-with-fade |
| `sys_culldist` | Дистанция отсечения симуляции (LOD cull) |

### 4. Viewport preview + симуляция

Два режима визуальной обратной связи — **статическое превью** (по умолчанию) и **live симуляция** (опционально).

**Статическое превью** — одна билборд-плоскость, child Empty'а, текстурированная спрайтом первого эмиттера системы и затонированная `color_start`. Нет анимации, нет спавна — просто показывает где живёт эффект и как он выглядит в момент рождения.

- Создаётся автоматически при создании 2DFX Particle или выборе имени эффекта.
- Обновляется при смене текстуры/цвета через кнопку **Обновить превью** (также автоматически после `Switch Emitter` и `Сохранить эффект`).
- Удаляется кнопкой **Удалить превью** (`gtatools.remove_2dfx_preview`).
- Поворот билборда обрабатывается фоновым таймером, выравнивающим quad с камерой активного 3D viewport'а.

**Live симуляция** — реальный GPU-driven симулятор частиц. Глобальный scene-toggle, работает на 30 Hz:

- Переключатель: **N-sidebar → 2DFX панель → Симуляция** чекбокс (иконка `▶` / `⏸` в зависимости от состояния). Scene property `gtatools_particle_sim`.
- При включении регистрирует `bpy.app.timers` tick на `1/30 s` и обходит все PARTICLE Empty в сцене.
- Каждый Empty получает child mesh `<empty_name>_psim` с пулом до **`MAX_PARTICLES_PER_EMITTER = 64`** quad'ов.
- Per-particle state (позиция, скорость, возраст, life) живёт в module-level dict'ах — эфемерный, не сохраняется в `.blend`.
- Quad'ы всегда смотрят на активный 3D viewport (orthonormal basis из `region_3d.view_rotation`).
- За кадром → particles тикают но mesh не обновляется.
- При выключении все `_psim` mesh'и удаляются.

> **Статическое превью** и **симуляция** могут работать одновременно — превью это «как эффект выглядит на скриншоте», симуляция для тюнинга emission/forces в движении. Симуляция гейтится глобально потому что каждый эмиттер потребляет немного CPU per tick (32 эмиттера × 64 частицы × 30 Hz = ~60K vector-операций/сек).

### 5. Кривые (анимация параметров)

Любой per-particle параметр можно сделать **анимированным по времени жизни** через piecewise-linear кривую. Кривые в runtime заменяют статические значения: вместо постоянного размера, движок сэмплирует размер из кривой по нормализованному возрасту каждой частицы.

**Где редактор:** прокрути за статическими свойствами вниз до секции **Particle Curves**.

**Workflow:**

1. Выбери канал кривой из dropdown — `SIZE.SIZEX`, `COLOUR.RED`, `COLOUR.GREEN`, `COLOUR.BLUE`, `COLOUR.ALPHA`, `EMRATE`, `EMSPEED` и т.д.
2. Появляется список ключей с `+` (добавить строку), `−` (удалить), UIList для выбора активной.
3. Каждая строка — пара `(TIME, VAL)`:
   - `TIME` ∈ `[0, 1]` — нормализованный возраст частицы (0 = рождение, 1 = смерть)
   - `VAL` — значение канала в этот момент
4. Ключи сортируются автоматически при записи.
5. Жми **Записать кривую в effects.fxp** для сохранения.

**Пример — рост размера для огня:**

```
SIZE.SIZEX:
  (0.00, 0.5)   ← рождение: маленький уголёк
  (0.30, 2.0)   ← пиковое пламя
  (1.00, 0.1)   ← смерть: рассеялся
```

**Пример — затухание цвета огня:**

```
COLOUR.RED:    (0.0, 1.0) → (1.0, 0.3)
COLOUR.GREEN:  (0.0, 0.8) → (1.0, 0.0)
COLOUR.BLUE:   (0.0, 0.2) → (1.0, 0.0)
COLOUR.ALPHA:  (0.0, 1.0) → (0.7, 0.5) → (1.0, 0.0)
```

> Кривые ПЕРЕОПРЕДЕЛЯЮТ статические `color_start` / `color_end` / `size_start` / `size_end` для своего канала. Чтобы отключить кривую — удали все ключи.

### 6. Системы с несколькими эмиттерами

Многие ванильные системы содержат несколько эмиттеров играющих одновременно. Пример: `prt_cardebris` имеет 4 эмиттера (куски, искры, пыль, дым) для одного эффекта взрыва машины.

- Dropdown **Switch Emitter ▾** в INU Particle Properties переключает между эмиттерами системы.
- У каждого эмиттера свой спрайт, blend, цвета, кривые — они независимы.
- При сохранении эффекта пишутся все эмиттеры.
- При создании нового эффекта через **New Effect** создаётся только **один** эмиттер — добавить ещё можно редактируя `effects.fxp` напрямую или клонируя multi-emitter шаблон.

### 7. Сохранение в effects.fxp

Один основной save-оператор (`gtatools.save_particle_effect`) с двумя режимами через popup-диалог:

| Поле | Что делает |
|---|---|
| `effect_name` | Имя целевой системы. По умолчанию — текущий выбранный эффект (сохраняет на месте); напиши новое имя → текущий эффект **клонируется** под этим именем. |
| `overwrite` | Если включён И таргет-имя уже существует — существующая система перезаписывается. Если выключен И имя есть → оператор выдаёт ошибку (защита от случайной перезаписи). Игнорируется если `effect_name` новое. |

Плюс два связанных оператора:

| Оператор | Что делает |
|---|---|
| **New Particle Effect** (`gtatools.particle_effect_new`) | Создать пустой новый эффект с нуля (не клон). Один эмиттер с текстурой `sphere`, белый цвет с alpha=0 на конце, life=1.0, rate=10. |
| **Delete Particle Effect** (`gtatools.particle_effect_delete`) | Удалить текущий выбранный эффект из `effects.fxp` после диалога подтверждения. |
| **Reload effects.fxp** (`gtatools.reload_effects_fxp`) | Сбросить in-memory FXP-кэш. Полезно если файл правился вне Blender и нужно чтобы dropdown / превью перечитали с диска. |

**Алгоритм Save — что происходит по клику:**

1. Перечитывает `effects.fxp` с диска (не из кэша — избегает stale state).
2. Если `effect_name` **новое** → deep-copy текущей системы, переименование, append.
3. Если `effect_name` **существует** + `overwrite` включён → переиспользует существующую систему на месте.
4. Вызывает `_apply_particle_props_to_emitter` который пишет **только поля которые ОТЛИЧАЮТСЯ** от текущего состояния эмиттера (dirty check):
   - Статичные поля (texture, blend, color, size, life, force и т.д.) сравниваются по одному.
   - Кривые с более чем одним keyframe'ом, статика которых совпадает — **НЕ трогаются** — сохраняет multi-keyframe анимации которые юзер не правил.
   - System header (`LENGTH`, `PLAYMODE`, `CULLDIST`) dirty-чекается отдельно.
5. **No-op early exit:** если не клонируем И ноль полей изменилось → сообщение «Нет изменений — файл не тронут», ничего не пишется.
6. **Auto-backup** при первой реальной записи в сессии — создаёт `effects.fxp.bak` (только если `.bak` ещё нет). Последующие записи бэкап не обновляют, поэтому `.bak` всегда состояние «начало сессии».
7. Запись файла с CRLF line endings, потом `clear_cache()` чтобы следующее открытие dropdown перечитало.

**Сохранение одной кривой** — отдельно — **Write Curve to FXP** (`gtatools.particle_curve_write`) пишет ТОЛЬКО редактируемую кривую (например `COLOUR.RED`), не трогая остальные кривые и скалярные поля. Используй для итеративного тюнинга кривых без полного сохранения системы.

> **Edit buffer:** при переключении dropdown на другой эффект все несохранённые правки сбрасываются до значений новой системы. **Сохраняй ДО переключения**, иначе работа потеряна.

### 8. Экспорт DFF

Привязка частицы хранится на Empty в виде custom property `2dfx_effect_name = '<system_name>'`. DFF экспорт читает это и пишет `PARTICLE` 2DFX entry в 2DFX-чанк DFF: **24-байтовая ASCII zero-padded строка** с именем системы (truncate если длиннее 24 символов).

Больше ничего экспортировать не нужно — параметры частиц живут в `effects.fxp`, не в DFF.

**Путь экспорта:** `File → Export → INU Export` (или N-panel → Export → DFF) → DFF подбирает каждый particle Empty запарентованный к мешу и выпускает по одному 2DFX entry на каждый.

### 9. В игре

1. Замени модель в `gta_sa/models/gta3.img` (используй **IMG Export** для пересборки архива с твоим DFF).
2. Замени `gta_sa/models/effects.fxp` на отредактированный файл.
3. Сделай бэкап ванильных файлов первым делом (всегда).
4. Запусти игру — частицы играют в локальной позиции Empty относительно модели, ориентированы по локальным осям эмиттера.

> Для тестов на **MTA:SA** workflow тот же, но частицы спавнятся только когда MOD-loaded модель с 2DFX-меткой в зоне видимости.

### Очистка материалов — подробно

Кнопка ищет датаблоки с суффиксом `.001`, `.002` и т.д. и объединяет их с оригиналом за один проход — отдельно материалы и отдельно текстуры (изображения).

**Материалы:**
- Все слоты `material_slots` у мешей, ссылающиеся на дубликат, переключаются на оригинал.
- Если оригинала с базовым именем нет — первый дубликат переименовывается в базовое имя и становится оригиналом.
- Неиспользуемые дубликаты (`users == 0`) удаляются из `bpy.data.materials`.

**Текстуры (безопасный режим):**
- Замена ссылки на изображение происходит в нодах `Image Texture` всех материалов **и** в node groups (shader/geometry/compositor).
- Дубликат объединяется с оригиналом **только если совпадает абсолютный путь к файлу** (`bpy.path.abspath` с учётом библиотеки). Это защита от ложных слияний для GTA SA, где одинаково названные текстуры часто приходят из разных TXD.
- Для packed/generated изображений (без filepath) используется слабый ключ `source + size`.
- Текстуры с разными путями **не объединяются** и попадают в счётчик «Пропущено».

**Отчёт в статус-баре:**
```
Материалов: 12/3 | Текстур: 8/2 | Пропущено (разные пути): 1
```
Формат — `объединено_слотов/удалено_дубликатов`.

### Скан файлов

**Sub-panel:** View3D → Sidebar (N) → GTA Tools → Проверка → Скан файлов

Линтит `.dff`, `.col`, `.txd` файлы **на диске** на crash-prone байтовые паттерны — без импорта в Blender. Полезно когда:
- собрал модели из разных источников и хочешь проверить перед паковкой в IMG;
- свежесобранная карта крашит игру и нужно найти виновника;
- аудитишь конвертированные/портированные модели (gmod → SA и т.п.).

**Workflow:**
1. Выбери папку через file picker.
2. Включи нужные форматы (DFF / COL / TXD).
3. По желанию включи «Включая подпапки». **Default off** — защита от случайного сканирования `gta_sa\models\`.
4. Жми **Сканировать**. Прогресс в status bar.
5. Результаты в скроллируемом списке: `severity_icon  filename: short message`. Клик на строку — полное описание, путь к файлу, кнопка «Открыть в Проводнике».
6. Фильтр «Только ERROR» (default on) скрывает WARN/INFO чтобы видны были только реальные крэши.

**Что проверяется:**

*COL — collision-формат*
- Magic + filesize header consistency
- Bounding sphere/box NaN/Inf или инвертированный (`min > max`)
- Sphere-collider radius validity, координаты вершин в `(−256, 256)` (int16/128.0)
- Индексы граней внутри vertex count
- Surface ID диапазон: vanilla ≤ 178, FLA ≤ 254
- Shadow mesh offset overflow (Manu-class crash `0x415D47`)
- Face-groups count в пределах 1024 (документированный лимит)

*DFF — RenderWare-модель*
- RW chunk integrity, RW version sanity (vanilla SA = `0x36003`)
- Atomic indices в frame/geometry массивах
- Frame parent-tree (без циклов и forward-refs)
- Per-geometry лимиты vertex/triangle/material (u16 hard + soft warnings)
- Кол-во UV-слоёв vs flag bits
- Skin PLG: bone count u8, max_weights ≤ 4, валидность bone-индексов
- Triangle.material в диапазоне
- NaN/Inf в позициях вершин, bounding sphere
- `GEOM_NATIVE` флаг (PS2/Xbox-only данные на PC engine)
- 2DFX entry count

*TXD — texture dictionary*
- `platform_id` (8 = D3D8, 9 = D3D9 — другое не загрузится на PC SA)
- Bit depth в `{4, 8, 16, 24, 32}`
- Power-of-two размеры (vanilla D3D8 path требует POT — известные крэши `0x004C9691` / `0x00732924` / `0x00749B7B`)
- DXT block alignment (×4)
- AUTO_MIPMAP флаг взаимно исключающий с `num_levels > 1`
- PAL + DXT взаимно исключающие
- Mipmap count vs `log2(max(w,h))`
- Пустые / дублирующиеся / слишком длинные имена текстур

Каждый код имеет развёрнутое объяснение в панели («Что это значит:») с описанием root cause и как чинить.

**Сохранение отчёта:**
Три варианта:
- 🟢 **Рядом с .blend** — default; warning если scene не сохранён.
- 🟡 **В папке скана**.
- 🟠 **Своя папка** — file picker.

Файл: `inu_lint_<timestamp>.txt` со сгруппированным результатом.

### Lint-профили

**Sub-panel:** View3D → Sidebar (N) → GTA Tools → Проверка → Lint Profile

Единый EnumProperty `gtatools_lint_profile` переключает набор thresholds/severity для **Сканера файлов** и **Анализатора карты**.

| Профиль | Что делает |
|---|---|
| **STANDARD** | По умолчанию — пороги откалиброваны против ванильных SA-ассетов (ноль false positives на reference-set `F:\AllDFF`) |
| **FLA** | Считает что установлен [Fastman92 Limit Adjuster](https://fastman92.com/) — глушит FLA-required warnings (Model ID > 19999, surface ID > 178 и т.п.) |
| **STRICT** | Жёсткие пороги (например material limit 50 вместо 100), для QA-прогона перед публикацией мода |
| **LENIENT** | Скрывает все INFO-уровень — полезно при аудите legacy-проектов где мелкие warnings — шум |

Активный профиль применяется и к **on-disk** (Сканер файлов), и к **cross-file** (Анализатор карты) проверкам. Переключение профиля пересчитывает результаты текущего скана — повторять не нужно.

### Анализатор карты (Game Validator)

**Sub-panel:** View3D → Sidebar (N) → GTA Tools → Проверка → Анализ карты

Кросс-проверка **IDE** файлов (определения) против **IPL** файлов (размещения) — ловит несовместимости которые приводят к крашу в игре.

**Режимы источника** (один из трёх):
1. **Из игры** — использует `gtatools_game_root` + резолвинг через `gta.dat` чтобы собрать все активные IDE/IPL пары.
2. **Из папки** — picker папки; рекурсивный обход на `.ide` и `.ipl`.
3. **Ручные списки** — UIList IDE-файлов + UIList IPL-файлов; кнопка «Добавить файл» для каждого.

**Опциональная IMG-проверка** — если передан список файлов в архиве, IDE entries проверяются против реального наличия DFF/TXD.

**Проверки:**
- **Висячие placements** — `INST` строка ссылается на model_id который ни в одном IDE не определён
- **Неиспользуемые ID** — IDE entry никогда не размещён в IPL (не крашит, но забивает stream slots)
- **Дубликаты ID** — один model_id определён в двух разных IDE
- **NaN координаты** — position/rotation содержит NaN или Inf
- **Interior range** — `inst.interior_id` вне `[0, 256]`
- **Draw distance sanity** — `drawdist` в IDE ≤ 0 или абсурдно большой
- **Отсутствующий TXD** — IDE ссылается на TXD которого нет в IMG (только в IMG-verify режиме)
- **Несоответствие полей** — IPL строка имеет неверное число comma-separated токенов

**Результаты** в UIList сгруппированы по severity (Critical / Warning / Info) с `LintIssue` shape общим со Сканером файлов. Клик по строке → полное описание + кнопка «Открыть IDE/IPL файл».

**Сохранение отчёта** — тот же 3-direction picker что у Сканера файлов.

## Texture Browser

**Sub-panel:** View3D → Sidebar (N) → GTA Tools → Texture Browser

Инвентарный инструмент для просмотра всех текстур из выбранного источника без импорта. Полезно когда:
- ищешь конкретную текстуру по имени среди множества TXD'ов;
- нужно понять «в каком TXD лежит `roof_tile_03`?»;
- проверяешь cross-ref что и где используется перед экспортом TXD-батча.

**Источники** (radio-селектор):
1. **Из IMG** — берёт каждый `.txd` внутри выбранного `.img` архива.
2. **Из папки** — рекурсивно обходит папку на `.txd` файлы.
3. **Из IDE-списка** — читает столбец `txd` в IDE-файлах и резолвит через `gtatools_game_root`.

**Строка UIList**: превью · `имя_текстуры` · `WxH` · формат · исходный `.txd`. Клик по строке загружает текстуру в превью-панель. Поиск-поле фильтрует по подстроке имени.

**Cross-reference** (toggle «used by»): для выбранной текстуры сканирует все материалы в текущем `.blend` и показывает какие объекты её используют. Клик по имени объекта — jump-select во вьюпорте.

Декодирование ленивое — заголовки текстур (имя + размер + формат) читаются upfront, пиксельные данные только при выборе строки. ~1000 текстур обычно сканируется меньше секунды.

## Персонажи (Skinned DFF)

**Импорт:**
- Armature с иерархией костей
- Vertex weights (скин)
- Bone matrices (Skin PLG)
- Совместимость с Kams Script и оригинальными моделями

**Экспорт:**

### Скомпилированные ноды

| Кнопка | Описание |
|--------|----------|
| Импорт NODES.dat | Загрузка бинарных нод (поддержка нескольких файлов одновременно) |
| Экспорт NODES.dat | Сохранение скомпилированных нод в выбранную папку |

**Импорт:** можно выбрать несколько файлов (nodes0.dat, nodes1.dat, ...) за раз. При импорте каждый объект получает свойство `nodes_filename` с именем исходного файла.

**Экспорт** работает в двух режимах:
1. **По имени файла** — если у объектов есть свойство `nodes_filename` (установлено при импорте), ноды группируются по исходным файлам и сохраняются с теми же именами
2. **Авто-разбиение по зонам** — объекты без `nodes_filename` автоматически распределяются по зонам карты GTA SA (сетка 8x8, 64 зоны, 750 единиц на зону). Каждая вершина попадает в зону по координатам: `gx = (X + 3000) / 750`, `gy = (3000 - Y) / 750`. Файлы сохраняются как `nodes0.dat` ... `nodes63.dat`

> **Сетка зон:** карта GTA SA: от -3000 до +3000 по X и Y. Зоны нумеруются слева направо, сверху вниз (zone = gy × 8 + gx).

### LightMap (beta_MTA)

**Панель:** View3D → Sidebar (N) → GTA Tools → Lightmap Generator (beta)

Генерация Lua кода для MTA SA скриптов лайтмапов. MTA скрипт в рантайме заменяет шейдеры на моделях, добавляя второй UV слой с лайтмапом поверх основных текстур.

**Полный порядок работы:**

1. **Создайте UV1** — основная развёртка для текстур модели (кирпичи, крыша и т.д.)
2. **Создайте UV2** — вторая развёртка специально для лайтмапа. Каждый полигон должен занимать уникальное место, без перекрытий. В Blender: UV Editor → UV → Smart UV Project или вручную
3. **Запеките освещение в текстуру по UV2** — используйте любой удобный способ запекания (Blender Bake, Cycles, сторонние аддоны). Главное — результат должен быть записан в текстуру по развёртке UV2
4. **Сохраните лайтмап** как PNG файл (например `lightmaps/building01.png`)
5. **Экспортируйте DFF** — убедитесь что в свойствах объекта включены оба UV слоя (`uv_map1` и `uv_map2`). Аддон запишет оба UV в DFF файл
6. **Генерируйте код:**
   - Выделите объект
   - Укажите **путь к лайтмапу** (относительный, как в ресурсах MTA)
   - Укажите **Model ID**
   - Нажмите **Генерировать**
7. **Скопируйте** результат в MTA Lua скрипт

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Загрузить лайтмап | `gtatools.load_lightmap` | Загрузить изображение лайтмапа для превью |
| Удалить лайтмап | `gtatools.remove_lightmap` | Удалить загруженный лайтмап |
| Генерировать | `gtatools.lightmap_generate` | Генерировать Lua код из текстур объекта |
| Копировать | `gtatools.lightmap_copy` | Копировать результат в буфер обмена |
| Очистить | `gtatools.lightmap_clear` | Очистить код |

**Результат:** Lua таблица с именами текстур и ссылками на лайтмап:
```lua
{
    textures = {
        "brick_wall",
        "roof_tile",
    },
    lightmap = "lightmaps/building01.png",
    models = {3500}
},
```

> **ВАЖНО:** UV2 обязателен — без второго UV слоя лайтмап наложится по координатам UV1 и будет выглядеть неправильно.

Сам MTA скрипт для лайтмапов доступен в разделе [Issues](../../issues) репозитория.

### Pipeline

Выбор рендер-пайплайна определяет как движок GTA SA обрабатывает модель:
- **None** — без пайплайна. Подходит для большинства объектов: мебель, заборы, растения, персонажи
- **Building** (0x53F2009A) — Day/Night vertex colors. Обязателен для зданий и объектов карты у которых есть vertex colors — без этого пайплайна цвета дня/ночи не будут переключаться при смене времени суток в игре
- **Reflections** (0x53F20098) — отражения на окнах. Только для моделей окон, которые должны отражать окружение. Окна должны быть отдельной моделью от здания

> 💡 **Пример:** дом `house01` должен иметь день/ночь освещение → Object Properties → INU Tools: Model → Pipeline = **Day/Night**. Окна этого дома вынеси в отдельный меш `house01_windows` → его Pipeline = **Reflections** чтобы они отражали улицу. Забор перед домом `house01_fence` → Pipeline = **None**.

### Normals

Переключатель **Normals** управляет экспортом нормалей вершин в DFF:
- **Включено** — модель получает динамическое освещение от движка GTA SA. Нужно для: персонажей, транспорта, оружия, интерактивных объектов
- **Выключено** — модель освещается только запечёнными vertex colors. Используется для: зданий, дорог, объектов карты

> 💡 **Пример:** CJ (персонаж) — ☑ Normals (его освещает движок в зависимости от солнца и фонарей). Здание на карте с запечёнными vertex colors — ☐ Normals (иначе движок сверху наложит своё освещение и картинка испортится).

## Asset Library

**Панель:** View3D → Sidebar (N) → GTA Tools → Asset Library

Собирает Blender Asset Library из любого набора IDE/IPL/IMG — vanilla SA, кастомной карты или мод-архива. Каждый проп становится mark-as-asset с превьюшкой, которую можно дропнуть в сцену из **Asset Browser** Blender'а.

**Workflow:**
1. **Сохрани .blend** — обязательно (билдеру нужна рабочая папка).
2. **Укажи Game Root + Регион** (в Setup-панели) — путь к папке с `gta_sa.exe`; регион сужает парсинг IDE/IPL.
3. **Извлечь ресурсы** — распаковывает кеш DFF/TXD/COL один раз. Повтор пропустит уже распакованное.
4. **Укажи папку Output** — пустая папка где будут лежать `.blend` библиотеки и превьюшки.
5. Жми **Собрать Asset Library**. Status text показывает фазу (cache scan → IDE read → preview gen → finalise).
6. **Edit → Preferences → File Paths → Asset Libraries → Add → твоя Output папка**.

После этого в Asset Browser появятся все ванильные пропы как drag-and-drop превьюшки.

**Опции:**
- *Размер превью (px)* — разрешение thumbnails (default 256, больше = медленнее но чётче).
- *Без превьюшек* — самый быстрый режим, использует Blender placeholder-иконки. Подходит для быстрых итераций.
- *Пропускать готовые .blend* — инкрементальная пересборка; обработаются только новые модели.
- *Перегенерировать превью* — повторный thumbnail-проход без перераспаковки.

> 💡 **Первая сборка медленная** (~15–30 мин для полной vanilla карты при 256 px; кастомные карты обычно собираются за минуты), пересборки — тоже минуты благодаря тоглу «Пропускать готовые .blend».

## Расширенные возможности

> Изначально добавлены в 1.6.4 как экспериментальные — за несколько релизов стабилизировались. Edge-case баги иногда всплывают; сообщайте о них в [Issues](../../issues).

### Map Export

Единый экспорт района сцены одной кнопкой: DFF + COL + TXD + IDE + IPL в одну папку.

**Где:** View3D → Сайдбар (N) → GTA Tools → панель *Map Export* → кнопка **Export Map…**

**Workflow:**
1. Выдели объекты, формирующие район (DFF меши, их LOD и COL — определяется по суффиксу/префиксу).
2. Жми *Export Map…*, выбери целевую папку.
3. Переключи что писать (DFF / COL / TXD / IDE / IPL) и опционально *Binary IPL*.
4. Задай *Base Name* (используется как имя общего TXD/IDE/IPL) и *ID Pool Start* (первый авто-присваиваемый Model ID для DFF с `model_id == 0`).

**Что делает:**
- Группирует объекты по базовому имени через `get_model_type()` — один DFF + опционально LOD + ноль-или-больше COL на группу
- Авто-присваивает Model ID из диапазона `[id_pool_start, 19999]` тем DFF у которых `inu.model_id == 0`, записывая обратно в объект
- Экспортирует per-group `*.dff` и `*.col` существующими экспортёрами
- **TXD: один `.txd` на каждое уникальное `inu.txd_name`** — DFF с одинаковым `txd_name` (например `vegas01.txd` шарится 50 зданиями) баккетятся в один общий TXD; DFF с собственным TXD (`cj.txd`) получают свой файл. Пустой `txd_name` фолбэчится на имя модели. Сохраняет ванильный SA-лейаут точно при импорте с IDE-заполненными `txd_name`
- **COL: одна `.col` библиотека на каждое уникальное `inu.col_name`** (при включённом тумблере `col_library`) — тот же паттерн что у TXD. `col_name` автоматически заполняется при Map Import именем исходного `.col` файла (`vegasN`, `LAs`, `LAn`, …). Round-trip восстанавливает оригинальный библиотечный файл со всеми моделями. Пустой `col_name` → fallback на `txd_name`, потом на имя модели. Если `col_library` выключен — вместо этого пишется отдельный `<base>.col` на каждую DFF
- Пишет один `{base_name}.ide` (секция objs) и один `{base_name}.ipl` (секция inst), покрывающие всю выборку
- Оператор работает как **модальный генератор** с window-manager таймером: статус-бар показывает текущую группу / TXD-бакет / IPL-стадию (`vegasN: TXD vegas02 (12 моделей)`), viewport остаётся отзывчивым, **ESC** отменяет экспорт.

Источник: [`tools/map_export.py`](INU_tools/tools/map_export.py).

#### Режимы разбиения (auto-split на районы)

Дропдаун **Разбиение** в сайдбаре диалога Map Export управляет тем, как выделение режется на отдельные district'ы при экспорте. Три режима:

| Режим | Имена district'ов | Когда использовать |
|---|---|---|
| **Без разбиения** (по умолчанию) | Один district с именем `base_name` | Маленькие хэндкрафтед карты, явное именование |
| **XY-сетка** | `<base>_x<cx>_y<cy>` на каждую непустую ячейку | Очень большие сцены (50k+ DFF), стриминго-чувствительные моды, совместное авторство по пространственным регионам |
| **По коллекциям** | Имя верхней коллекции на каждый бакет | Round-trip с Group-by-IPL импортом — `vegasn_stream0` в Blender → `vegasn_stream0.ipl` на выходе |

##### XY-сетка

Координата world-origin `(x, y)` каждой DFF делится на `cell_size` и округляется вниз (floor) — получается индекс ячейки `(cx, cy)`. LOD/COL-сиблинги едут вместе со своим DFF; принадлежность к ячейке решается только по DFF. Каждая непустая ячейка становится подпапкой `<base>_x<cx>_y<cy>` внутри target_dir (отрицательные индексы получают префикс `m`, например `district_xm3_y1` — чтобы имя папки никогда не начиналось с минуса). Если разбиение даёт ровно одну ячейку, оператор тихо откатывается к *Без разбиения* — поэтому держать режим включённым на маленькой сцене безопасно.

**Гайд по cell_size:** 256 м соответствует ванильному радиусу стриминга SA (модель в ячейке N становится видимой игроку примерно при заходе в ячейки N±1). 128 м для очень плотных интерьеров; 512 м или 1024 м когда большинство моделей — крупные террейн-меши (хайвэи, реки).

##### По коллекциям

Биннит DFF по имени верхней пользовательской коллекции (той, что лежит прямо под scene root'ом). Имя коллекции становится именем district'а — то есть коллекция `vegasn_stream0` в outliner произведёт `vegasn_stream0.ipl`, `vegasn_stream0.ide`, `vegasn_stream0.col`, `vegasn_stream0.txd` внутри `target_dir/vegasn_stream0/`. Это естественный round-trip для *Map Import → Group by IPL → правка → реэкспорт*: оператор Map Import именует родительские коллекции под имена исходных IPL, а реэкспорт в режиме *По коллекциям* восстанавливает оригинальную структуру district'ов.

DFF, лежащие только в scene root коллекции (или вообще без коллекции), попадают в бакет `unsorted/`. Если только один бакет содержит DFF, оператор откатывается к *Без разбиения* — поэтому этот режим тоже безопасно держать включённым на маленькой curated-сцене.

Источник: [`tools/map_export.py`](INU_tools/tools/map_export.py) → `compute_grid_cells`, `compute_collection_cells`, `format_cell_name`, `_build_top_collection_lookup`, `export_map(..., split_mode='GRID' | 'COLLECTION', cell_size=...)`.

### Binary IPL Write

Добавляет запись в формате `bnry` в IPL-экспортёр (чтение уже было).

**Где:** File → Export → *Export IPL* → чекбокс **Binary (bnry)**.

### UV-анимация в DFF

Запись простой линейной U/V-прокрутки прямо в бинарь DFF через чанки `0x2B` (словарь UV-анимаций) + `0x135` (UV anim PLG на материале).

**Где:** Properties → Material → *GTA SA Material Effects* → блок **Писать UV Anim в DFF**.

**Поля:**
- **Писать UV Anim в DFF** — чекбокс включает запись чанков при экспорте
- **Speed U / Speed V** — скорость сдвига по осям в единицах UV в секунду
- **Длительность** — длина цикла анимации в секундах

**Как кодируется:** два keyframe'а (t=0 с identity-трансформом, t=duration со сдвигом = speed × duration), `node_to_uv[0] = 1` — привязка к первому слоту текстуры. Для циклических сдвигов (конвейеры, вода) выбирай duration так, чтобы `speed × duration` был целым числом UV-единиц.

**Round-trip:** обратное чтение реализовано — импорт UV-анимированного DFF заполняет `mat.inu.uv_anim_write/speed_u/speed_v/duration` по dict'у 0x2B уровня clump и PLG 0x135 на материале. Импортер считает 2-keyframe линейную кодировку writer'а канонической: берёт последний keyframe (`trans_u/v`) и делит на `time` чтобы восстановить скорость. Hand-edited многокадровые анимации при повторном экспорте сплющиваются в ту же пару speed/duration (промежуточные ключи пока не сохраняются).

Источник: [`core/dff.py`](INU_tools/core/dff.py) → `UVAnim`, `UVAnimDict`, `_uv_anim_plg_bytes`, `_read_uv_anim_dict`, `_read_uv_anim_plg`; [`ops/dff_export.py`](INU_tools/ops/dff_export.py) → `_collect_uv_anim_dict`; [`ops/dff_import.py`](INU_tools/ops/dff_import.py) → `_apply_uv_anim_to_material`.

#### Пошаговый гайд

**Кейсы** — конвейеры и эскалаторы, поверхности воды/лавы, бегущие неоновые вывески, скроллящиеся билборды, двигающиеся текстуры на мельницах. Везде где геометрия на месте, а текстура «плывёт».

**1. Тайлящаяся текстура.** Края должны совпадать — слева↔справа и сверху↔снизу — иначе каждый цикл виден шов. Типичные размеры 128×128 или 256×256. Для конвейера: чёрная лента с тремя жёлтыми полосами на равных расстояниях → скролл на высоту одной полосы за цикл = ощущение «бесконечной» ленты.

**2. UV-развёртка.** Выдели face loop в Edit Mode, сделай unwrap. UV должны покрывать **полный диапазон 0..1** (или точные tiled-множители 2×/3×). UV-квадратик 0.2..0.5 будет скроллиться, но показывать только 30% текстуры.

**3. Материал.** Image Texture нода с тайлящейся текстурой, подключенная к BSDF Color. Открой Properties → панель Material → блок *UV Animation*:

- ☑ **Писать UV Anim в DFF** — включает чанки 0x2B + 0x135 на экспорте.
- **Speed U** (единиц в секунду) — `+` скроллит вправо, `−` влево.
- **Speed V** (единиц в секунду) — `+` вниз, `−` вверх.
- **Длительность** — длина цикла в секундах.

**4. Подбор Speed и Длительности.** Для бесшовного цикла `Speed × Длительность` должно быть **целым UV-числом** (1, 2, 3…). Если `Speed × Длительность = 0.7` — текстура дёргается на каждой склейке цикла.

| Эффект | Speed U | Speed V | Длительность | Сдвиг за цикл |
|---|---|---|---|---|
| Медленный конвейер вниз | 0 | 0.5 | 2.0 | 1 V-единица |
| Быстрая лента влево | −2.0 | 0 | 1.0 | 2 U-единицы |
| Неон бегущая строка вправо | 1.0 | 0 | 4.0 | 4 U-единицы |
| Вода (диагональ) | 0.2 | 0.1 | 5.0 | 1 U + 0.5 V |

**5. Экспорт.** Любой DFF-экспорт (одиночный DFF, Export All, Export to IMG) подхватывает флаг `uv_anim_write` материала и пишет чанки анимации. В IDE никаких дополнительных флагов не нужно — движок активирует анимацию по наличию чанка `0x135` на материале.

**6. Проверка в игре.** Клади DFF в IMG, **Rebuild Archive** в IMG-туле (иначе игра покажет старую закешированную версию), загружай сейв рядом с моделью. Если анимация не работает:

- Импортни свой же экспортированный DFF обратно через INU Tools 1.6.7 — read-back должен автоматически восстановить те же Speed U/V + Длительность на материале. Если они пустые — export не записал чанки (проверь галку).
- `node_to_uv[0] = 1` ставится автоматически; сбить в all-zeros — анимация останется в файле но движок не привяжет её к слоту текстуры.
- Скролл «дёргается» на стыке цикла → `Speed × Длительность` не целое. Подкрути одно из двух чтобы произведение легло на целое число.

**Ограничения 2-keyframe линейной модели:**
- Нет вращения и easing'а — только скролл с постоянной скоростью. Крутящиеся колёса или пульсирующие эффекты требуют hex-редактора или кастомных DFF-патчей.
- Один скролл на материал — слоистый скролл (передний ×2, задний ×1) нужны два материала или shader-трюки.
- Round-trip чужих hand-edited DFF с многокадровой UV-анимацией сплющивает промежуточные ключи в линейные endpoints. Не блокер для файлов сделанных аддоном, но знать стоит если пересохраняешь чью-то ручную UV-анимацию.

### Менеджер текстур (Bitmaps Manager)

Утилиты управления текстурами и материалами в одной панели: поиск недостающих файлов, resolve из папки, batch-копирование, дубликаты, очистка неиспользуемого, плюс операции над материалами (check/cleanup/sort).

**Где:** View3D → Сайдбар (N) → GTA Tools → панель *Менеджер текстур*.

**Layout:** компактные 3 строки:

| Строка | Содержимое |
|---|---|
| **Сканировать** + бейдж `Пропущено: N` | главный entry-point — статус «сколько файлов не находится» |
| **Текстуры ▾** + бейдж `Неисп: I/M` | dropdown с 5 операциями (см. ниже). Бейдж `I/M` = unused images / unused materials |
| **Материалы ▾** | dropdown с 3 операциями над материалами |

**Дропдаун «Текстуры»:**
- **Найти в папке…** — рекурсивно обходит папку, матчит по basename (с расширением или без), патчит `image.filepath` и делает reload.
- **Скопировать в папку…** — копирует все используемые хотя бы одним материалом текстуры в целевую папку. Опция **Subfolder per TXD** создаёт `target/{txd_name}/texture.png` (обходит мешей и читает `obj.inu.txd_name`).
- **Найти дубликаты** — MD5-хэширует каждый файл текстуры, выводит группы идентичных файлов в System Console.
- **Найти неиспользуемые** — сканирует `bpy.data.images` и `bpy.data.materials` на orphan'ы (нет users в сцене). Бейдж `Неисп: I/M` обновляется.
- **Удалить неиспользуемые…** — destructive action: удаляет ранее найденные orphan'ы (popup с подтверждением).

**Дропдаун «Материалы»:**
- **Проверка материалов** — лог в System Console: материалы без текстуры, с дублями, конфликтами эффектов.
- **Очистка материалов** — удаляет orphan slots, мерджит дубли, нормализует имена.
- **Сортировка материалов** — алфавитная сортировка material slots в активном объекте (для предсказуемого порядка в DFF).

Источник: [`tools/bitmaps_manager.py`](INU_tools/tools/bitmaps_manager.py).

### CST IO

Текстовая сериализация данных COL-коллизии, совместимая по духу со Steve's COL Editor. Альтернатива бинарному `.col` для ручного редактирования или diff'а.

**Где:** Операторы `gtatools.import_cst` / `gtatools.export_cst`.

**Формат:** построчный, одна директива на структуру. Поддерживается несколько MODEL-блоков в файле.
```
MODEL my_col
ID 1234
VERSION 3
BOUNDS 0 0 0 5.0 -2 -2 -2 2 2 2
SPHERE 0 0 1 0.5  0 0 0 0
BOX -1 -1 0 1 1 2  0 0 0 0
VERTEX 1.0 2.0 0.0
FACE 0 1 2  0 0 0 0
SHADOW_VERTEX 0 0 0
SHADOW_FACE 0 1 2  0 0 0 0
END
```

Каждый `SPHERE` / `BOX` / `FACE` заканчивается 4 токенами поверхности: `material flags brightness light`. Всё после `#` — комментарий.

Источник: [`core/cst.py`](INU_tools/core/cst.py), [`ops/cst_import.py`](INU_tools/ops/cst_import.py), [`ops/cst_export.py`](INU_tools/ops/cst_export.py).

### Vehicle Scale Helper

Пропорциональное масштабирование всей иерархии машины (Empty-корень + меши + дамми-дети) с сохранением структуры для DFF-экспорта.

**Где:** View3D → Сайдбар (N) → GTA Tools → панель *Машины* → кнопка **Масштаб машины…** (также доступен как оператор `gtatools.vehicle_scale` для скриптов).

**Опции:**
- **Factor** — множитель равномерного масштаба
- **Dummies Only** — если включено, двигаются только дамми-Empty, вершины мешей остаются в прежнем размере

**Что делает:** обходит иерархию DFS, умножает `obj.location` каждого объекта на factor, сбрасывает `matrix_parent_inverse` в identity, применяет `Matrix.Scale(factor)` к данным меша (копирует shared-меши) и Armature, сбрасывает `scale` в `(1,1,1)` на каждом объекте. Empty display size тоже масштабируется.

Источник: [`tools/vehicle_scale.py`](INU_tools/tools/vehicle_scale.py).

### Vehicle Damage Variants

Управление парами `_ok` / `_dam` атомиков кузова машины. Движок GTA SA автоматически переключает видимый меш между двумя вариантами при повреждении панели — единственный контракт это naming convention: атомик с суффиксом `_ok` и атомик с суффиксом `_dam` (с одинаковым префиксом) образуют пару, например `bonnet_ok` ↔ `bonnet_dam`, `door_lf_ok` ↔ `door_lf_dam`.

**Где:** View3D → Сайдбар (N) → GTA Tools → панель *Машины* → блок **Damage variants**.

**Операторы:**

| Кнопка | Что делает |
|---|---|
| **Создать _dam** (`gtatools.vehicle_add_damage_variant`) | Дублирует данные активного меша в новый объект `<base>_dam`, парентит к тому же Empty что у источника. Если у источника нет суффикса `_ok` / `_dam`, он автоматически переименовывается в `<имя>_ok`. Новый `_dam` получает `hide_viewport=True`, чтобы по умолчанию пользователь видел OK-состояние — DFF-экспорт обходит всю иерархию независимо от viewport-флага, поэтому вариант всё равно попадает в `.dff`. |
| **Показать OK / Dam / Оба** (`gtatools.vehicle_show_damage`) | Переключает `hide_viewport` для каждого `_ok` и `_dam` меша в иерархии активного объекта (или по всей сцене если активного нет). `OK` показывает `_ok`, скрывает `_dam`. `Dam` показывает `_dam`, скрывает `_ok`. `Оба` показывает всё (полезно для дебага). Влияет только на viewport — DFF-экспорт не трогает. |
| **Проверить пары** (`gtatools.vehicle_pair_report`) | Обходит активную иерархию и пишет в системную консоль: парные `_ok+_dam` меши, одиночные `_ok` (без пары `_dam`), одиночные `_dam` (без пары `_ok`). В статус-баре отчитывается сводкой; если есть одиночные — уровень `WARNING`. У одиночных частей не будет повреждённого варианта в игре (движок ищет пару при загрузке). |

**Туториал — повреждение капота:**

1. Смоделируй целый капот, назови меш `bonnet_ok`. Поставь его под Empty `bonnet_dummy` для трансформа петли.
2. Выдели `bonnet_ok` → нажми **Создать _dam**. Появится новый меш `bonnet_dam` той же формы, скрытый во viewport.
3. Нажми **Показать Dam** → OK-меш скрывается, повреждённый становится видимым. Отредактируй меш (придави вершины внутрь, добавь вмятины).
4. **Показать OK** для быстрого сравнения. **Показать Оба** если хочешь видеть оба меша одновременно (удобно сохранять консистентный силуэт).
5. Запусти **Проверить пары** — должно отчитаться `1 пара, 0 одиночных`. Добавь `door_lf_ok`/`_dam`, `boot_ok`/`_dam`, повтори.
6. Экспортируй DFF как обычно — оба варианта поедут в `.dff`. В игре движок переключает их по здоровью компонента.

**Заметки:**
- Hide-on-create действует только на viewport (`hide_viewport`). Render-флаг не трогается, поэтому коллекционные экспортёры (Map Export, Export to IMG) не теряют вариант.
- Используй **Показать OK** перед экспортом, если нужен чистый превью-скриншот DFF — `_dam` меши обычно косметически уродуют кадр.
- `wheel_*` и `*_dummy` Empty в ванильном SA не имеют damage-варианта — только крашенные кузовные части (chassis, двери, капот, бамперы, лобовое стекло, mudguards, багажник) идут с парами `_ok` / `_dam`.

Источник: [`tools/vehicle_scale.py`](INU_tools/tools/vehicle_scale.py) → `_strip_damage_suffix`, `find_damage_pairs`, `GTATOOLS_OT_vehicle_add_damage_variant`, `GTATOOLS_OT_vehicle_show_damage`, `GTATOOLS_OT_vehicle_pair_report`.

### Train Station Markers

Видимые Empty-сферы на кривых train-треков в каждой точке-станции, чтобы станции были видны в Object mode без входа в Edit mode.

**Где:** Оператор `gtatools.refresh_station_markers` (активная track-кривая с `path_type == 'track'`).

**Что делает:** стирает старые маркеры, прикреплённые к треку, читает `station_indices` (устанавливаемые существующим `gtatools.mark_station`), размещает Empty-сферу в каждой станции с `empty_display_size = 3.0`, парентит к треку с identity-parent-inverse, чтобы локальная позиция совпадала с точкой кривой 1:1.

Источник: [`ops/ifp_import.py`](INU_tools/ops/ifp_import.py) → `_refresh_station_markers`, `GTATOOLS_OT_refresh_station_markers`.

### Roadblocks & Traffic Lights

Редактор per-node флагов для кривых paths.ipl: бит roadblock + тип светофора.

**Где:** Edit Curve mode на кривой с `path_type == 'path_ipl'` → оператор `gtatools.path_node_flag` с действиями:
- **Toggle Roadblock** — переключает бит 12 (барьер копов) на каждой выделенной точке
- **Clear / Normal / Rail / Bus Traffic Light** — ставит биты 8–11 в 0 / 1 / 2 / 3

Работает на отфильтрованных точках сплайна, но пишет в оригинальные IDProp-слоты (которые включают empty-padding ноды из формата 12-на-группу в IPL).

Источник: [`core/paths.py`](INU_tools/core/paths.py) → константы флагов + `decode_node_flags` / `encode_node_flags`; [`ops/ifp_import.py`](INU_tools/ops/ifp_import.py) → `GTATOOLS_OT_path_node_flag`.

### FLA4 Path Format

Расширенный формат `nodes*.dat` от Fastman Limit Adjuster 4. Добавляет 12 байт на path-ноду (spawn probability, speed limit в км/ч, lane count override) поверх ванильной 28-байтной структуры, итого 40 байт на ноду.

**Детекция:** файл считается FLA4 если начинается с ASCII-магии `FLA4`. Layout счётчиков и смещений в остальном идентичен ванильному.

**Где:** File → Export → *Export Path Nodes* → чекбокс **FLA4 Format**. Импорт определяет автоматически.

Источник: [`core/paths.py`](INU_tools/core/paths.py) → `FLA4_MAGIC`, `FLA4_PATH_NODE_SIZE`, FLA4-ветки в `read_nodes` / `write_nodes`; [`ops/path_export.py`](INU_tools/ops/path_export.py) → `export_nodes(..., fla4=True)`.

### Модули ядра

#### dff.py — RenderWare DFF
Чтение/запись бинарных RW потоков. Поддерживает: Clump, Frame List, Geometry List, Geometry (вершины, нормали, UV, vertex colors), Material List, Material, Texture, Atomic, **Skin PLG** (веса костей), **2DFX PLG** (Light / Particle / Ped Attractor / Sun Glare), **BinMesh PLG**, **MatFX PLG** (env map / bump / reflections), **UV Animation Dictionary** (chunk 0x2B), **Native Data PLG** (mobile геометрия), **HAnim PLG** (bone hierarchy), **breakable objects** (chunk 0x253F2FD). Round-trip сохраняет не-Clump первые чанки.

#### col.py — Формат коллизий
Поддержка COL1, COL2, COL3 (стандарт GTA SA), COL4. Чтение/запись: полигоны, вершины, группы, **сферы**, **боксы** (через empties с `display_type='CUBE'`), свойства поверхностей (материал, флаги, яркость, day/night light nibbles).

#### txd.py + dxt.py — Текстуры
Pure-numpy DXT1/BC3 энкодер/декодер (~7× быстрее NVTT). Форматы: DXT1, DXT3, DXT5, RASTER_8888, RASTER_888 (32-bit BGRX), RASTER_565, RASTER_1555, RASTER_4444, PAL8. Платформа: D3D8/D3D9. Опциональный `dxt_gpu.py` для compute-shader пути.

#### txd_mobile.py — Mobile TXD контейнер
Детект 4-файлового мобильного контейнера (`.pvr` / `.etc` / `.dxt` + `.txt` / `.toc` / `.dat` / `.tmb`). Pixel-декодирование делегировано TxdGen (нет in-tree PVRTC/ETC1 кодека).

#### ide.py + ide_flag_translate.py — Item Definition
Все секции: objs (статика), tobj (time-based), anim (анимированные), cars (транспорт), peds (пешеходы), weap (оружие), hier (иерархия), txdp (TXD-родители). Per-game перевод бит флагов в `ide_flag_translate.py` — один логический флаг (например "drawlast") имеет разные битовые позиции в III/VC/SA.

#### ipl.py — Item Placement
Все секции: inst (экземпляры), cull (zones), grge (гаражи), enex (input/exit), pick (pickups), cars (припаркованные), auzo (audio zones), jump (трюковые прыжки), occl (occlusion), tcyc (time cycle), zone (zones). Поддерживает **текстовый** и **бинарный** IPL (`bnry`). FLA `real_interior` (12-я колонка) опционально.

#### img.py — IMG архивы
v2 (GTA SA) и v1 (GTA III/VC). Context manager `ImgReader` для быстрого sequential чтения. Функции: `read_directory`, `extract_file`, `replace_or_add`, `remove_file`, `create_img`. Sector-aligned (2048 байт).

#### ifp.py — Анимации
Три суб-формата: **ANP3** (SA), **ANPK** (III/VC), **ANP2** (custom). `source_format` сохраняется при round-trip. KF time канонически в **секундах**; импортёр конвертирует.

#### paths.py — Данные путей
- `paths.ipl` — vehicle/pedestrian path текстовый формат
- `tracks.dat` — ж/д пути
- `nodes*.dat` — скомпилированные бинарные path nodes (vehicle / ped / navi) с FLA4 расширением и структурированным `navi_links` / `link_lengths` / `path_intersections` post-link tail

#### fxp.py — Particle Effects File
Pure-text effects.fxp парсер. Иерархия dataclass: `FXFile → FXSystem → FXEmitter → FXInfoBlock`. Кривые хранятся как `FXCurve` с piecewise-linear `sample(t)`. CRLF output сохраняется. `load_cached(path)` с invalidation по mtime.

#### water.py — water.dat
Quad-определения с per-vertex flow speed (X/Y/Z) и water type (0–3). MTA round-trip совместим.

#### gta_dat.py — Game Data
Парсинг `gta.dat`, `gta_int.dat`, `default.dat`. Извлекает пути IDE/IPL/IMG в порядке объявления. `extract_regions()` возвращает имена папок из MAPS для динамического region filtering.

#### game_versions.py — Multi-game детект
Детектит III / VC / SA по сигнатурам контента (RW версия, IPL header markers, IDE column counts). `game_of_scene(scene)` возвращает активную игру; `game_of_file(path)` для stand-alone детекта.

#### file_lint.py + lint_profile.py + map_lint.py — Линтинг
- `file_lint.py` — on-disk DFF/COL/TXD сканер; выдаёт `LintIssue(code, severity, file, message)` записи.
- `lint_profile.py` — STANDARD / FLA / STRICT / LENIENT профили переопределяют дефолтные пороги + post-filter issues по code/severity.
- `map_lint.py` — cross-file IDE↔IPL валидатор (висячие ссылки, дубликаты ID, IMG cross-verify).

#### vc_layers.py — Vertex Color Layers
Pure-logic naming и composite math (Photoshop-style layers). `recompose_stack(mesh, scope)` блендит `VCL_<scope>_*` слои в `Day` / `Night` базовые атрибуты.

#### rwbinary.py — RenderWare Chunk Helpers
Low-level утилиты для dff/txd/col writer'ов: chunk header pack/unpack, выравнивание, RW version encoding.

#### validate.py — Pre-export Sanity Checks
Нормализация кватернионов, проверка paintjob `_ok ↔ _dam` пар, sanity модулюции цвета, детект дубликатов model_id.
